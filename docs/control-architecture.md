# 客户端本地中控与策略控制

WebUI 是 **导播客户端本机的中控台**。页面与本机 HTTP 接口随 Fabric Mod 打包，由 Mod 执行控制；服务端插件不托管网页、不开放控制端口。已接入统一播放队列、本地自动补足、启停、目标、镜头、AI 本机配置、连接测试和文本策略调用。Dynmap 导入及热力分析的范围见下文数据说明。

## 职责

Mod 持有真实执行状态，负责播放队列、本地目标选择、镜头轨迹、平滑运动、输入优先级、断线降级、场景世界检查。自动补足只向队尾添加合法候选，在场景与玩家都存在时按约 80% / 20% 抽选；它不代表已识别建筑密度或热点。本地巡游、地图导入、AI、队列和运镜默认可用，服务不可用时仍可手动拉取本机配置的外链；玩家观察必须得到配套插件的实时许可。

服务端插件提供世界巡游范围、排除区、玩家拒绝/黑名单/冷却、当前Paper后端的完整可公开玩家名单、手工场景分页与外链世界映射。巡游名单只约束自动巡游、本地自动补点及 AI 补点，名单外仍能手动展示、入队和申请真实玩家预告。数据读取只检查真实账号的数据权限和存储状态；摄影机观察者模式、实际观察位置和隐私在玩家会话执行时检查。Dynmap JSON 不经过服务端；Mod 直接访问外链、解析与缓存。Mod初始化即异步预取默认Hyperion/Paralon地图，不阻塞客户端或资源包；进入匹配世界后等原版资源包和世界加载完成、连续稳定2秒再安全应用，复用有效缓存或同源在途请求，过期刷新。其余来源手动拉取，均不持续轮询。持续玩家轨迹与热力采集未实现，默认不采样。

协议 v7 保留独立 `WorldPolicy` 下发当前世界 key/UUID、`automaticPatrol` 和完整排除区，不依赖地图是否配置。握手先送规则、再回数据连接结果，心跳补发，世界与巡游名单变更即时同步。客户端按精确服务器地址与世界持久化非玩家规则；插件失联不删除已知巡游范围和排除区。已发现插件但当前连接尚未同步时暂缓自动选择；超时沿用已有规则，无规则时回退本地策略。手动景点不等待服务器候选刷新或玩家时长请求，玩家请求则等待其独立会话流程。

客户端统一检查巡游资格：AI 输入、异步结果、本地随机补充与自动出队均受约束；名单移除使旧 AI 结果失效，清理自动待播与自动当前项，保留手动项。名单外空队列暂停基础巡游，已手动选择的场景正常运镜。`worlds.yml` v2 的 `automatic-patrol: false` 只关闭自动能力，保留场景和排除区；v1 自动迁移为 true，重新 add 可恢复。玩家黑名单/冷却通过服务端名单的UNAVAILABLE与会话拒绝执行，不向摄影机公开具体隐私原因，尚未实现独立全量/增量隐私同步。

WebUI 的地图配置按精确服务器地址与世界保存本机 URL、Dynmap 世界名，保存命令同时校验当前上下文，防止跨服或跨世界的旧草稿写入。保存不发 HTTP，保留用户显式设置的本机来源。内置默认来源为 Hyperion 地址 `https://map.bilicraft.com/s2/hyperion/` 与 Dynmap 世界名 `Paralon`，在Mod初始化时即异步预取，不依赖进服或打开中控；有效缓存和同源在途请求复用，缓存过期正常刷新，不由定时器或页面轮询重复下载。BiliCraft主世界未保存本机覆盖时，`ConnectionSession`仍要求匹配世界进服就绪后才应用结果；下载不阻塞客户端或原版资源包，结果在客户端主线程安全应用。手动拉取若遇加载则延后执行，下载结果先排入客户端主线程，加载结束后再应用；改来源、切世界或断线丢弃旧上下文的应用请求和待应用结果，不把默认缓存误套到其他世界。其他服务器/世界通过手动本机映射或已授权的服务端映射接入，并手动拉取；清除本机覆盖后恢复相应默认或服务端来源。切换来源或上下文会使旧应用请求失效，服务端已知排除区仍在最终执行层检查。本机功能可用与服务端授权分别展示，不把本机模式伪装为玩家观察许可。

本地网页采用宽屏三栏工作台：**左侧播放队列、中央位置示意图、右侧可搜索素材库**，顶部固定启停、跳过和刷新，底部为可折叠、互相切换的游戏聊天和操作记录。队列显示当前、下一项和待播顺序；素材库包含玩家、观景点、巡游区域，可添加到队尾、下一项或指定位置，也可立即插播。工作台提供实时运镜选择与常用参数滑杆，独立配置页集中管理完整配置。页面显示实际客户端账户与可读取的本机头像，读取失败时使用文字占位，不伪造在线状态。运行状态明确区分正常运行、仅手动与地形保护；仅手动时说明当前WorldPolicy限制自动巡游/补队，提示管理员使用/director worlds list和add，不由网页绕过规则。

中央示意图使用现有候选坐标，包括本机导入的 Dynmap 标记；不显示游戏视频或地图站点的栅格瓦片。拖动、缩放和选择示意图目标不直接移动游戏摄影机。场景不受附近距离或预加载限制。入镜机位按当前摄影机相对目标的 XZ 方向确定，实际三维距离 ≤128 格时使用 FLY 平滑飞行，>128 格时由本人账号发送同世界 OP 传送命令；未加载区块不将 FLY 升级为 TP。起镜前短暂遮挡并直接对齐，飞行过程正常显示，入镜期间暂停场景排播倒计时；到位且目标区块加载后开始展示，失败或超时跳过。FLY 途中实时改变距离、绝对 Y 或模式时重新规划飞行，仍不升级为 TP。玩家名单不按距离或已加载实体过滤，跨世界只展示状态；同世界AVAILABLE目标走15秒预告、最多15秒授权接近和Ready确认，服务端实际≤96格再开始跟随。玩家素材没有公开坐标，不在中央示意图伪造位置。

游戏画面左上角在导播运行时显示当前排播目标的名称，观景点、巡游区域和玩家共用当前队列项作为来源，切换目标立即更新；不使用摄影机或玩家坐标推断地区。没有当前目标或停止导播时隐藏。Dynmap 多边形元数据仍保留，名称清理 HTML 及 `§`/`&` 颜色、样式码后统一以白字绘制。

`ShotTransition`管理250毫秒淡出、构图准备和750毫秒淡入。准备期间保持遮罩与零速度，在真实世界状态和目标校验通过后直接设置当前yaw/pitch及Entity.lastYaw/lastPitch，解除准备状态后才淡入，不把初始朝向调整交给转向限速器。TP到达不直接解除遮罩；FLY仅在起镜时准备朝向，遮罩不跟随整个飞行过程。玩家授权入镜、挂机点和跟拍结束的退让也在遮罩下直接对齐。停止、跳过、切世界及断线清除准备状态，场景准备期间暂停计时。

`CameraMotion`继续生成以保存的绝对Y或玩家跟拍偏移为基准的构图，`CameraTerrainAvoidance`在运动平滑前选择临时安全目标，不改写`CameraSettings`。普通镜头先检查同高角度候选，再搜索有界抬升；基础路线连续安全2秒后以0.5格/秒恢复临时高度，保存绕行侧与候选角度以减少频繁换向。规划间隔250毫秒；`CameraTerrainWorld`在客户端主线程查询扩大后的摄影机碰撞盒、扫掠路径和目标视线，每个实例限制8192估算方块扫描。未加载区块或预算不足返回UNKNOWN，不能作为安全机位或安全路径。构图视线允许目标末4格被建筑或地形占据，以兼容位于建筑内部的地图锚点。

FLY由已验证的至多4格局部路径段逐步接近目标，未知远端仅允许沿已确认的局部空间前进，不将FLY升级TP；有惯性的实际下一步独立进行扫掠硬校验，普通镜头及结束跟随后的退让都不能据此穿山。TP在遮罩下完成落点加载与空间、视线验证，最多两次安全机位修正，失败优先返回最近已确认机位；回退仍失败且当前位置未确认安全时保持遮罩、暂停排播。CameraTerrainRecovery在连接/世界就绪后每250毫秒重查当前占用，只有CLEAR才恢复排播和补队；UNKNOWN/BLOCKED保持等待，手动Stop清除恢复意图。解锁不直接清除ShotTransition遮罩，仍由revealShot完成构图校准后淡入；也可手动选择远处场景。世界边界、高度和排除区检查继续约束机位及路径。服务器`IdlePoint`在避障入口前锁定位姿并返回，完全跳过该偏移。本地避障不执行全局寻路，不保证封闭或复杂地形存在可达路线；详见[地形避障说明](terrain-avoidance.md)。

外链解析后对完整候选按稳定ID排序选取代表点：同类型、清理后同名且与已保留代表点水平距离≤128格时不重复纳入素材库。保留原始ID、坐标和远处同名地点，不将多个点平均到新坐标，也不通过近邻链条继续吞并远处标点。全部有效区域多边形独立保留，筛选只减少可排播候选；导入状态报告合并数。

解析先识别BiliCraft的main/title包装，只读取标题，丢弃style/script内容和隐藏的创建信息。名称准入规则在48字符截断前执行，拦截纯ASCII点分层级标识、明确铁路技术标记及残留样式片段；系统世界边界按原始marker ID识别，不按“世界边界”名称误删同名建筑。车站、正常英文名称、星门和正常插件地区保留，不整层禁用Residence或公会。有效多边形仍保留；过滤仅控制地图候选，不改变世界政策的排除区。旧地图磁盘缓存回退时也复用名称准入规则。

聊天由 Mod 在游戏线程维护最多 100 条纯文本接收缓冲，断线清空、不写盘；页面用 `textContent` 显示，不解析 HTML、链接或服务器消息中的点击按钮。单行输入最多 256 字符，普通消息与 `/命令` 共用入口，调用当前本人账号的 Minecraft 原生发送方法，不能绕过聊天限制或服务器命令权限。发送失败保留当前页面的草稿，成功再清空；WebUI 发送不额外调用原生命令历史写入。上述内存约束不改变 Minecraft 自身和服务器原有日志行为，不承诺服务器无日志。

网页通过同一 Mod 状态和操作入口控制游戏，不能自行签发玩家观察许可。AI 仅接收结构化文本并返回队尾目标建议，不输出键鼠事件或直接操纵游戏对象，不维护另一套执行器。

## 全服玩家分页

完整名单来自当前Paper后端的Bukkit在线集合，排除摄影机本人、camera.canSee不可见、隐身和vanished玩家，不依赖距离、当前客户端实体或TAB页内容。其他世界返回OTHER_WORLD；同世界普通玩家依据活动、隐私/排除区/已有会话等返回AVAILABLE、IDLE、SPECTATOR或UNAVAILABLE，只允许AVAILABLE入队和申请观察。名单只带UUID、name、world、availability，不包含位置或轨迹；拒绝/黑名单具体原因不在摘要中分发。当前没有跨代理多后端汇总。

SnapshotRequest带单调正数requestId；服务端SnapshotPages将玩家和场景分开分页，每页最多32玩家或32场景，最多4096玩家、256总页。32个最大长度场景的编码为19,703字节，低于30,000字节包限；不能通过截断名单规避上限，超限明确报错。客户端SnapshotAssembly绑定requestId、连接代次和世界，收齐全部页、校验索引和跨页身份唯一后再整体应用；缺页/超时保留已有列表，迟到回复不能混入新连接或新世界。玩家数据不写入场景缓存。详细字段见[共享协议](../protocol/README.md)，行为与限制见[全服名单](full-player-roster.md)。

## 本机接口

从 Mod 菜单手动打开本地中控，才启动 `127.0.0.1` 上的随机可用端口并打开入口；默认不启动网页服务，不监听局域网或公网。关闭客户端时一并关闭本机服务。

`GET /api/state` 读取真实本机状态；`POST /api/command` 提交启停、上一素材插播、跳过当前、刷新、展示所选目标、队列增删/移动/时长调整、队列配置、镜头配置和 AI 提供方配置，以及 `aiTest` 连接测试。聊天状态为 `chat.connected`、`chat.messages`（`id/text/receivedAt`）与 `chat.maxLength`；发送使用 `{"action":"chatSend","message":"单行消息或 /命令"}`，原生发送后仍以服务器回执判断实际命令结果。AI 状态提供启用、请求中、连接测试、模型列表、最近策略状态、最早下次请求时间与会话用量。HTTP 层只处理本机鉴权、大小限制和异步回执；只有客户端游戏线程读取或修改 Minecraft 状态。

页面每秒读取本地状态，不因此读取Dynmap、执行热力采样或写盘，也不直接触发游戏服务器快照。首次Hello获授权时，Mod自动请求一次完整玩家/手工场景分页；导播运行且autoFill开启、未暂停、没有业务占用时，队列逻辑最多每60秒刷新一次，不再要求地图候选不足。地形保护等阻塞状态解除后继续正常刷新；手动刷新/上一素材仍受现有协议与限流约束。

每次本机服务启动生成新的随机会话令牌，通过入口 fragment 交给页面，再用自定义请求头发送；页面清除地址栏 fragment，令牌只保留于该浏览器会话。接口检查精确 Host、Origin 和令牌，不允许跨源读取；静态资源采用固定白名单，不提供任意文件服务。

命令正文限制为 16 KiB UTF-8 JSON。等待游戏线程最多 2 秒，超时取消尚未执行的任务并返回失败；页面区分请求接受与后续状态同步，不将请求已发送显示成已应用。HTTP 失败时停止提交新修改，待成功同步后再恢复；保存期间的新草稿不被轮询覆盖。状态接口只返回密钥是否存在，不返回密钥；新输入密钥不写入网页记录或浏览器本地持久化。AI 配置只保存到已有的本机配置文件，不发送给服务端。

手动停止优先，玩家隐私、排除区和游戏命令权限始终生效；巡游名单不限制手动展示。网页停止与游戏内停止调用同一逻辑，断开网页不会把已停止的导播重新开启。切到玩家时仍重新预告 15 秒，不能绕过拒绝或冷却；服务端失联时停止玩家观察，非玩家展示继续遵守已知巡游范围与排除区。

未来如需远程访问，必须另行明确部署位置、认证和访问范围，不能把本机中控自动改成公网服务。

## 播放队列与时长

自动待播目标数默认 4，可配置为 1～12；待播队列最多容纳 64 项。自动选择排除当前与已排目标，只补队尾，不重排人工项。人工插入、移除与排序按条目 ID 操作，箭头通过相对移动在游戏线程计算位置，避免旧快照索引移动错误条目。编辑停止状态下的队列不会自动开播。

`ShowcaseQueue` 以目标ID维护当前轮的已播集合；场景到达并开始展示、玩家获准且实际进入跟拍时标记，不把入镜失败或预告拒绝当成已播。`fill`和AI候选准备共用随机抽样，排除当前、待播、已播及冷却中的目标，同批不重复，维持场景80%/玩家20%的倾向；AI回包入队时再次检查已播。开启自动续排且当前项/待播均结束时，`beginNextRound`检查当前世界合法候选全部已播，保留未播退避目标的等待语义；没有候选或全部仍在退避时不换轮。只清除本次候选的已播记录，不清除其他世界进度或任何退避/冷却。记录最后实际播出的ID，在可用替代点中随机挑下一轮首项并本地先入队；单个合法点允许循环，其他点处于退避时等待而不立即重播末项。随后沿用本地/AI补点，轮内无重复。控制器在菜单暂停、地图/快照加载、业务请求未完成或退让未结束时不换轮，换轮使旧AI请求失效但保留60秒间隔。`targetWithinRules`与`targetAvailable`共享世界/权限/边界等校验，前者供换轮识别暂处退避的合法目标，后者继续应用执行退避。停止/启动及跨世界清队列保留已播记录，JOIN/DISCONNECT重置；集合只在内存中，不向AI或持久化文件传输玩家记录。手动插播和手动待播仍允许重播。

服务器挂机点由`IdlePoints`按世界UUID原子保存到`idle-points.yml`，失败回滚内存，不依赖世界是否加入自动巡游名单。`/director idle set [x y z yaw pitch]`、`info`、`clear`以真实发送者校验`bilicraftdirector.idle.manage`（默认OP），设置时检查当前世界高度、边界和排除区。客户端`/directoridle`只是原生命令上传入口，不先行更新点位，不再读取本机挂机点文件。协议v7保留`IdlePointSync`（worldKey和可空完整机位），在成功握手、心跳、世界切换和修改时同步给有数据权限的当前世界导播；空机位表示删除或当前边界规则不允许，客户端拒绝其他世界数据。客户端`IdlePoint`将服务端姿态映射为保留ID的场景，进入既有队列/AI且不混入场景磁盘缓存，WebUI标记为IDLE。切入使用真实本人tp请求，等待到达及加载后在运动入口固定位置与yaw/pitch并返回，跳过`CameraMotion`和全局运镜参数；自动规则、场景时长和已播名单仍适用。修改/清除正在播出的点先停播，过时待播机位拒绝执行；失联、断线及切世界清除客户端点位。协议升级保留本地v4/v5/v6无玩家场景缓存和v5/v6世界政策的明确布局迁移，不接受旧v6及更早网络包头。

场景默认计划 120 秒，范围 30～600 秒；菜单、游戏暂停或场景入镜途中不消耗场景播放时间。当前与下一项卡片均提供 ±10 秒，按具体条目 ID 应用；当前场景剩余归零后按队列继续。跳过当前项不重排其余条目。队列条目保存在内存，不承诺跨世界、断线或重启恢复；队列参数单独保存到本机。

玩家条目创建时确定 180～480 秒计划，默认在该范围本地随机选取；下一项可在范围内 ±10 秒。开始播出时通过v7 `ObserveRequest`提交计划，服务端返回带sessionId的NOTICE。15秒私密预告后重新校验，进入最多15秒APPROACHING，仅向获准摄影机发送此刻的PlayerView目标姿态。Mod在遮罩下准备机位，必要时由本人原生命令发送数字坐标tp，等待真实区块、目标实体、当前位置和视线安全后发送ObserveReady(sessionId,targetId)。服务端重新检查同世界、实际距离≤96格及权限/隐私，再回FOLLOWING并从此开始计算总时长；准备超时、拒绝、远距传送或离线立即结束。预告与接近均不消耗跟随时间，实体未加载不再把远处在线玩家从名单删掉。

当前玩家 ±10 秒必须通过 `DurationRequest` / `DurationReply` 由真实摄影机账号的自有会话处理。收到核准前不本地加长倒计时；服务端严格检查总时长范围及差值，NOTICE/APPROACHING中调整不重置各自准备截止时间，FOLLOWING截止时间始终由原开始时间加总时长计算。合法缩短使截止时间已过时正常结束，非法调整用独立拒绝回执保留有效跟随。拒绝、黑名单、无动作、传送或失权始终优先，调整不能复活已结束会话。

## 已实现的客户端配置

实时区与配置页共用 `camera` 操作。实时切换与拖动以 `persist:false` 应用最新一组参数，连续输入合并、请求串行；点击保存时才持久化，状态明确区分已应用与已保存。配置页的显式保存先取消未发送预览、等待在途预览，避免旧实时参数覆盖较新配置。未应用的配置草稿独立保留。仅调整速度/转向或保存相同设置不会重置轨迹相位，模式/距离/高度变化通过统一的速度平滑与转向限制过渡，停止时编辑不启动导播。

| 配置 | 默认值与范围 | 本机行为 |
| --- | --- | --- |
| 运镜模式 | 默认 ORBIT；可选 AUTO、FOLLOW、DOLLY、TRUCK、CRANE、PAN、STATIC | 自动、跟拍、环绕、推进/拉远、横移、升降、摇镜、静机位；统一经过本地执行检查 |

上述默认镜头值不覆盖用户已经显式保存的配置。镜头、队列与 AI 配置均写入客户端本机，保存配置不会自动启动导播。API Key 需为不含空白的 ASCII 字符串；空输入保留已有密钥，明确清除才删除。AI 配置保存不代表连接、鉴权或 Chat 能力验证成功。`aiTest` 只对当前已保存的提供方请求 `GET /models`，模型可暂留空，不发聊天请求、不启用策略；模型列表可读取不证明 Chat 权限或非思考参数可用。

配置页只读展示 `StrategyPrompt` 版本、固定规则、最多 12 个候选的动态小表和 `{"picks":["c1"]}` 输出结构。短 ID 到真实目标的映射不发送给模型；玩家名称统一为 `player`。预览不触发请求。实际策略只在运行、未暂停、自动补足开启且需要合法候选时请求；成功建议通过游戏线程重新检查后补到队尾，不重排人工项。两次尝试至少间隔 60 秒，超时、失败和非法输出同样占用间隔，随后使用本地默认策略。页面显示本次客户端会话的请求数与提供方返回的 token 用量；用量未返回单独计数，不视作零消耗。详见 [AI 决策契约](ai-decision-contract.md)。
