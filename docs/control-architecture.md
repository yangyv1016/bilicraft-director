# 客户端本地中控与策略控制

WebUI 是 **导播客户端本机的中控台**。页面与本机 HTTP 接口随 Fabric Mod 打包，由 Mod 执行控制；服务端插件不托管网页、不开放控制端口。已接入统一播放队列、本地自动补足、启停、目标、镜头、AI 本机配置、连接测试和文本策略调用。Dynmap 导入及热力分析的范围见下文数据说明。

## 职责

Mod 持有真实执行状态，负责播放队列、本地目标选择、镜头轨迹、平滑运动、输入优先级、断线降级、场景世界检查。自动补足只向队尾添加合法候选，在场景与玩家都存在时按约 80% / 20% 抽选；它不代表已识别建筑密度或热点。本地巡游、地图导入、AI、队列和运镜默认可用，服务不可用时仍可手动拉取本机配置的外链；玩家观察必须得到配套插件的实时许可。

服务端插件负责世界允许名单、玩家拒绝/黑名单/冷却、手工场景快照与外链世界映射。Dynmap JSON 不经过服务端；Mod 手动直连外链、解析与缓存。持续玩家轨迹与热力采集未实现，默认不采样。

WebUI 的地图配置按精确服务器地址与世界保存本机 URL、Dynmap 世界名，保存命令同时校验当前上下文，防止跨服或跨世界的旧草稿写入。保存不发 HTTP，本机配置优先；清除后可使用已授权的服务端映射。切换来源或上下文会使旧请求失效，服务端已知排除区仍在最终执行层检查。本机功能可用与服务端授权分别展示，不把本机模式伪装为玩家观察许可。

本地网页采用宽屏三栏工作台：**左侧播放队列、中央位置示意图、右侧可搜索素材库**，顶部固定启停、跳过和刷新，底部为可折叠操作记录。队列显示当前、下一项和待播顺序；素材库包含玩家、观景点、巡游区域，可添加到队尾、下一项或指定位置，也可立即插播。工作台提供实时运镜选择与常用参数滑杆，独立配置页集中管理完整配置。页面显示实际客户端账户与可读取的本机头像，读取失败时使用文字占位，不伪造在线状态。

中央示意图使用现有候选坐标，包括本机导入的附近 Dynmap 标记；不显示游戏视频或地图站点的栅格瓦片。拖动、缩放和选择示意图目标不直接移动游戏摄影机。

网页通过同一 Mod 状态和操作入口控制游戏，不能自行签发玩家观察许可。AI 仅接收结构化文本并返回队尾目标建议，不输出键鼠事件或直接操纵游戏对象，不维护另一套执行器。

## 本机接口

从 Mod 菜单手动打开本地中控，才启动 `127.0.0.1` 上的随机可用端口并打开入口；默认不启动网页服务，不监听局域网或公网。关闭客户端时一并关闭本机服务。

`GET /api/state` 读取真实本机状态；`POST /api/command` 提交启停、上一素材插播、跳过当前、刷新、展示所选目标、队列增删/移动/时长调整、队列配置、镜头配置和 AI 提供方配置，以及 `aiTest` 连接测试。AI 状态提供启用、请求中、连接测试、模型列表、最近策略状态、最早下次请求时间与会话用量。HTTP 层只处理本机鉴权、大小限制和异步回执；只有客户端游戏线程读取或修改 Minecraft 状态。

页面每秒读取本地状态，不因此读取 Dynmap、执行热力采样或写盘，也不直接触发游戏服务器快照。候选不足时，Mod 的队列逻辑最多每 60 秒自动尝试刷新一次；手动刷新/上一素材仍受现有协议与限流约束。

每次本机服务启动生成新的随机会话令牌，通过入口 fragment 交给页面，再用自定义请求头发送；页面清除地址栏 fragment，令牌只保留于该浏览器会话。接口检查精确 Host、Origin 和令牌，不允许跨源读取；静态资源采用固定白名单，不提供任意文件服务。

命令正文限制为 16 KiB UTF-8 JSON。等待游戏线程最多 2 秒，超时取消尚未执行的任务并返回失败；页面区分请求接受与后续状态同步，不将请求已发送显示成已应用。HTTP 失败时停止提交新修改，待成功同步后再恢复；保存期间的新草稿不被轮询覆盖。状态接口只返回密钥是否存在，不返回密钥；新输入密钥不写入网页记录或浏览器本地持久化。AI 配置只保存到已有的本机配置文件，不发送给服务端。

手动停止优先，服务端隐私与世界约束始终强制。网页停止与游戏内停止调用同一逻辑，断开网页不会把已停止的导播重新开启。切到玩家时仍重新预告 15 秒，不能绕过拒绝、冷却或世界许可；服务端失联时仍只保留本地巡游与非玩家缓存。

未来如需远程访问，必须另行明确部署位置、认证和访问范围，不能把本机中控自动改成公网服务。

## 播放队列与时长

自动待播目标数默认 4，可配置为 1～12；待播队列最多容纳 64 项。自动选择排除当前与已排目标，只补队尾，不重排人工项。人工插入、移除与排序按条目 ID 操作，箭头通过相对移动在游戏线程计算位置，避免旧快照索引移动错误条目。编辑停止状态下的队列不会自动开播。

场景默认计划 120 秒，范围 30～600 秒；菜单或游戏暂停时不消耗场景播放时间。当前与下一项卡片均提供 ±10 秒，按具体条目 ID 应用；当前场景剩余归零后按队列继续。跳过当前项不重排其余条目。队列条目保存在内存，不承诺跨世界、断线或重启恢复；队列参数单独保存到本机。

玩家条目创建时确定 180～480 秒计划，默认在该范围本地随机选取；下一项可在范围内 ±10 秒。开始播出时通过 v3 `ObserveRequest` 提交计划，由服务端返回实际核准总时长。15 秒私密预告仍是单独窗口，不计入跟随时长。

当前玩家 ±10 秒必须通过 `DurationRequest` / `DurationReply` 由真实摄影机账号的自有会话处理。收到核准前不本地加长倒计时；服务端严格检查总时长范围及差值，NOTICE 中调整不重置预告，FOLLOWING 截止时间始终由原开始时间加总时长计算。合法缩短使截止时间已过时正常结束，非法调整用独立拒绝回执保留有效跟随。拒绝、黑名单、无动作、传送或失权始终优先，调整不能复活已结束会话。

## 已实现的客户端配置

实时区与配置页共用 `camera` 操作。实时切换与拖动以 `persist:false` 应用最新一组参数，连续输入合并、请求串行；点击保存时才持久化，状态明确区分已应用与已保存。配置页的显式保存先取消未发送预览、等待在途预览，避免旧实时参数覆盖较新配置。未应用的配置草稿独立保留。仅调整速度/转向或保存相同设置不会重置轨迹相位，模式/距离/高度变化通过统一的速度平滑与转向限制过渡，停止时编辑不启动导播。

| 配置 | 默认值与范围 | 本机行为 |
| --- | --- | --- |
| 运镜模式 | 默认 AUTO；可选 FOLLOW、ORBIT、DOLLY、TRUCK、CRANE、PAN、STATIC | 自动、跟拍、环绕、推进/拉远、横移、升降、摇镜、静机位；统一经过本地执行检查 |
| 机位半径 | 默认 12 格，6～24 格 | 实际路径也受目标区域半径限制 |
| 移动速度 | 默认 2.5 格/秒，0.5～5 格/秒 | 平滑趋近目标机位，保持本地速度上限 |
| 高度偏移 | 默认 4 格，1～12 格 | 目标上方的基础机位偏移 |
| 运动幅度 | 默认 8 格，2～24 格 | 用于推进、横移、升降、摇镜及自动区域巡游，按路径范围收紧 |
| 转向速度上限 | 默认 30 度/秒，6～80 度/秒 | 限制镜头追向目标的角速度 |
| 自动补足 | 默认开启 | 只准备队尾条目，不代替手动启动 |
| 自动待播数 | 默认 4，1～12 | 候选不足时保留现有队列与基础巡游 |
| 默认场景时长 | 默认 120 秒，30～600 秒 | 只作为新场景条目的计划，不覆盖既有条目 |
| AI 提供方 | DeepSeek / OpenAI | 各自保存基础地址、模型与遮挡密钥；可保留或明确清除已有密钥 |
| AI 策略启用 | 默认关闭 | 显式启用并保存后，运行中的自动补足可按需请求模型；不自动启动导播 |

镜头、队列与 AI 配置均写入客户端本机，保存配置不会自动启动导播。API Key 需为不含空白的 ASCII 字符串；空输入保留已有密钥，明确清除才删除。AI 配置保存不代表连接、鉴权或 Chat 能力验证成功。`aiTest` 只对当前已保存的提供方请求 `GET /models`，模型可暂留空，不发聊天请求、不启用策略；模型列表可读取不证明 Chat 权限或非思考参数可用。

配置页只读展示 `StrategyPrompt` 版本、固定规则、最多 12 个候选的动态小表和 `{"picks":["c1"]}` 输出结构。短 ID 到真实目标的映射不发送给模型；玩家名称统一为 `player`。预览不触发请求。实际策略只在运行、未暂停、自动补足开启且需要合法候选时请求；成功建议通过游戏线程重新检查后补到队尾，不重排人工项。两次尝试至少间隔 60 秒，超时、失败和非法输出同样占用间隔，随后使用本地默认策略。页面显示本次客户端会话的请求数与提供方返回的 token 用量；用量未返回单独计数，不视作零消耗。详见 [AI 决策契约](ai-decision-contract.md)。

## 尚未接入

- Dynmap 栅格瓦片底图；当前已支持客户端直连外链标记/区域并转换为附近候选。
- 持续热力采集、热点权重、建筑密度识别与路线自动生成；已有本地候选池按 80% / 20% 抽选补队尾。
- 跨世界/远距离传送、完整路线编辑与物理路径约束。

人工策略、AI 建议与本地默认策略在 Mod 内统一验证并执行。AI 响应绑定运行代次、配置版本与世界；手动停止或上下文失效后丢弃旧结果，不能用迟到回包重新开播。构建、真实 HTTP、浏览器页面与实际 Fabric 运行的验证范围分别见 [验证记录](validation-stage1.md)，不以夹具测试代替真实付费 API 验证。
