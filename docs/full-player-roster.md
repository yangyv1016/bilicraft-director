# 全服玩家名单与授权观察

客户端0.1.7、服务端0.1.3和内嵌协议模块0.1.3使用wire v7，须同时升级。旧v6只支持旧消息布局，不能与本版混用；本地旧场景/世界规则缓存的布局迁移不代表网络兼容。

## “全服”的范围

插件在Paper主线程读取当前后端的`Bukkit.getOnlinePlayers()`，不以摄影机距离、客户端已加载实体或TAB列表作为名单来源。以下玩家不分发：摄影机本人、已离线、`camera.canSee(target)`不可见、隐身或`vanished`元数据为真的玩家。Paper 1.21.11会自动给原版观察者设置隐身标志；Bukkit不能区分该标志与主动隐身，因此普通观察者通常也不公开，不能用SPECTATOR状态绕过隐身过滤。当前不汇总Velocity/BungeeCord等代理下的其他Paper后端，也不读取Dynmap玩家位置代替真实在线名单。

其他可公开玩家均列入摘要，只有`UUID`、账号名、实际世界registry key和可用状态，不含坐标、朝向或活动时间。其他世界也显示，但不能自动跨世界观察。服务器隐私、世界边界和排除区仍是执行权威，列出名字不等于授权跟随。

| 状态 | 含义 | 可申请观察 |
| --- | --- | --- |
| AVAILABLE | 同世界、非观察者、近期有活动，当前服务端条件允许 | 是，仍需后续预告与重新校验 |
| OTHER_WORLD | 与摄影机不在同一世界 | 否，不自动跨世界传送 |
| IDLE | 同世界目标连续10秒无记录到的活动 | 否，后续刷新可更新 |
| SPECTATOR | 同世界目标处于观察者模式 | 否 |
| UNAVAILABLE | 当前有隐私、冷却、已有会话或活动区域等限制 | 否，不公开具体隐私原因 |

状态以这次服务器快照为准，不保证在点击时仍有效。服务端会在每个授权阶段重新检查，不能依靠旧摘要绕过拒绝、长期黑名单或冷却。玩家摘要不写入磁盘场景缓存，也不在本机示意图中伪造坐标。

## 完整分页与刷新

`SnapshotRequest(requestId)`使用客户端单调递增的正数ID，服务端在每个`SnapshotPage`中回显。`SnapshotPages.create`将玩家页和场景页分开发送，每页最多32玩家或32场景；空响应也发送1个空页。

- 全量最多4096玩家、8192场景，且玩家页与场景页合计最多256页。服务端手工配置仍是每世界最多64场景，本机Dynmap候选另有自己的4096项限制。
- 每包上限30,000字节；32个最大字段长度的场景编码为19,703字节。触及总量/页数上限时明确拒绝，不静默裁剪后称为全服名单。
- 客户端同时绑定requestId、当前世界和连接代次。收齐全部页并检查页数、索引及跨页玩家UUID/场景`(world,id)`唯一后才整体替换；缺页、畸形或超时不应用半份名单。
- 切世界、断线或新请求使旧上下文失效；迟到分页不能覆盖新世界或新连接。玩家数据仍仅保存在会话内存中。

首次`HelloReply`获授权后自动请求一次，不需要先启动导播或等待景点不足。后续导播运行、自动补足开启且未暂停、没有业务请求占用时，最多每60秒刷新一次，即使地图已经有足够景点也会刷新。世界/资源加载、菜单暂停、地形保护或在途请求可能推迟刷新；手动刷新使用同一入口，保留一秒响应间隔和请求串行限制。网页每秒读取本机状态不等于每秒向服务器重新查询。

每次完整查询在服务端处理在线集合、状态检查和稳定排序，不做区块扫描、地图HTTP下载或持续玩家轨迹采样；每次响应的工作量随当前在线人数和场景数增长。4096是协议边界，不是该人数下的实测负载承诺。

## 从预告到真实跟随

1. 摄影机选择同世界AVAILABLE玩家，发送`ObserveRequest`。服务端按真实发送账号检查数据权限、观察者模式、目标资格、隐私/冷却、区域和并发会话，持久预留完整期限后进入NOTICE。
2. 目标收到只有本人可见的15秒预告及拒绝/长期黑名单按钮。摄影机此时没有目标坐标许可，不接近、不开始跟随；按钮关联具体会话。
3. 预告结束后再次检查条件，进入最多15秒的APPROACHING。只有这个状态向对应摄影机发送会话ID及此刻`targetPose`；该姿态不进入全服摘要，也不持续广播目标位置。
4. Mod在遮罩下准备玩家镜头。已在可确认的近处可直接等待到位；需要远距接近时，由摄影机本人发送`minecraft:tp @s <数字x> <数字y> <数字z>`，继续依赖本人原生命令权限。目标玩家不被传送，不使用其名字拼接传送命令。
5. 客户端确认真实当前世界、目标实体和区块已加载、机位占用及目标视线安全，且距离不超过96格，才发送`ObserveReady(sessionId,targetId)`。UNKNOWN不能作为安全或到位证明，发出TP也不代表已经到达。
6. 服务端按真实摄影机会话重新验证身份、目标、实际同世界距离≤96格及全部权限/隐私条件，返回FOLLOWING后才开始180～480秒跟随计时。NOTICE和APPROACHING均不占正式跟随时长。

旧会话的Ready被忽略，不能结束或启动后续会话。接近超过15秒、命令未获准或实体/安全一直未就绪会结束本次观察，不绕过加载检查强行开镜；玩家拒绝、黑名单、至少32格传送、跨世界、离线、隐藏、进入排除区或摄影机失权等撤销规则在准备和跟随阶段继续生效。目标连续10秒无动作也会结束。

`/director stop`、可点击拒绝以及`/tell 摄影机账号 停止跟随`继续有效；主动拒绝冷却24小时，正常结束冷却30分钟，长期黑名单直到本人解除。摄影机的本机WebUI不能自行签发任何阶段的服务器许可。

## 自动补队与“运行中却为空”

完整名单解决的是素材来源，自动补队仍服从巡游资格。管理员使用`/director worlds list`查看实际世界名与巡游开关，再用`/director worlds add <实际已加载世界名>`启用；对应权限为`bilicraftdirector.worlds.manage`。不要把地图能下载、景点能手动播放或导播开关已开启，当作该世界已获自动巡游资格。

WebUI显示“仅手动”时，名单外仍可手动选景点、插队或按完整授权流程申请玩家；它不会绕过`WorldPolicy`。显示“地形保护”时，是当前机位未确认安全导致的执行暂停；世界就绪后每250毫秒仅在CLEAR时解除，再经正常构图/淡入继续补队。UNKNOWN和BLOCKED不会解锁，手动停止后不自动恢复。

候选全部不可用、已排/本轮已播、处于退避、资源加载或请求未完成等情况也可能暂时没有新项，不能只凭“运行中”判断故障。完整请求的状态、巡游状态和地形保护状态应分别查看。

## 验证边界

协议单元测试已验证超过旧128人限制的180玩家与70场景无损分页、4096人/256页边界、畸形包和会话姿态约束。它们是纯Java测试，不代表4096真实客户端负载或Paper游戏内授权执行已经实测。
