# BiliCraft 导播 v0.1.12

客户端启动后自动监听本机中控，保留的网页可在客户端重启后自行恢复连接；提前统一规划地表高度、运镜与自动拉远，减少台阶地形上的停走和环绕折返；新增可筛选、导出的玩家观察事件记录。

| 安装包/模块 | 版本 | 升级要求 |
| --- | --- | --- |
| Fabric 客户端 | 0.1.12 | 退出客户端后替换旧 Mod JAR，保留配置 |
| Paper 服务端 | 0.1.3 | 本次未修改；已安装 0.1.3 无需替换 |
| 内嵌协议模块 | 0.1.3 | 随客户端打包，通信协议仍为 wire v7 |

客户端0.1.7～0.1.12均兼容服务端0.1.3；旧v6组合不能与v7混用。Minecraft仍为1.21.11，Java为21。

## 自动连接本机中控

- 客户端启动完成即监听回环端口，不自动打开浏览器或启动导播。默认16360，占用后按既有规则顺延。
- 网页通过严格同源入口取得新的本机会话。保留同一页面时，客户端退出后显示等待，再次启动会自动重连当前地址；未保存草稿保留，失败命令不重放。
- 本次升级后先刷新一次旧网页以加载新逻辑。实际端口改变时从游戏F9菜单或`/directorweb`打开新地址；页面不会扫描其他端口。

## 运镜平滑

- 在避障选角前，先读取原候选机位及附近路线的真实已加载地表，统一规划临时高度和自动拉远，减少镜头为了维持低Y而切到相反方位。
- 连续ORBIT/AUTO提前外推局部路线，临时高度稳定两秒后按每秒0.5格回落；必须原地爬升或等待地形时暂停运镜相位，恢复后不追赶。
- 保存的高度、距离和其他镜头参数不改写。实际下一步的最低离地、碰撞、未知区块、世界边界和排除区检查保留；玩家跟拍与固定挂机点保持各自规则。复杂地形仍可能安全等待，不保证任意地形可达。

## 玩家观察事件

- 中控底部打开“事件与操作 → 玩家观察”，查看申请、预告、入镜、跟随、时长调整和结束；显示客户端记录时间、玩家名、来源及原因。
- 拒绝、长期黑名单、离线等原因不再被下一目标覆盖。Mod保留最近200条观察事件，网页按历史与事件ID恢复去重，支持JSON导出；“清空显示”只影响当前页面。
- 事件同步写入Minecraft标准日志，客户端退出后的旧记录可搜索`[ObservationEvent]`。不记录观察授权ID、网页令牌、坐标、聊天原文或API Key；服务端合并原因原样显示，不推测未说明的隐私状态。
- 只记录与本摄影机有关的事件；没有当前观察会话的全服黑名单增删不会广播到这里。不更改预告、拒绝、冷却或授权规则。

## 验证与范围

- 本地`build release`及440项JUnit通过：客户端322、协议54、服务端64，失败、错误与跳过均为0；另有6组网页事件、9组网页自动重连的实际函数回归及规范复核。
- 真实开发客户端两次启动、同一浏览器页面无刷新重连通过；未保存队列草稿保留，网络观察中没有自动命令或开播。
- 真实隔离Fabric/Paper屋顶运镜120.194秒、1202个已知地表样本：最低离地16.405格、最大俯仰45°，无额外传送、水平完全停顿或反向折返，正向环绕147.85°。
- 真实隔离服和浏览器验证拒绝、黑名单、离线、手动停止、过期按钮及完整观察流程；15.004秒预告后入镜，实际点击`+10秒`由服务器核准217→227秒，27条唯一事件与游戏日志及导出一致。筛选、折叠重开、聊天切换、清空防重放和刷新恢复均经实际点击验证。
- 以上游戏验证使用同功能源码的开发客户端。最终云端安装JAR未另行启动；正式服长期直播、所有运镜与自然地形组合未由这次样本覆盖。服务端和协议源码未修改。
