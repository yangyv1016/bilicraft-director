# BiliCraft 导播 v0.1.9

视线遮挡现在只检查镜头前方8格，避免远处建筑、地图锚点或远端未加载区块让场景无法入镜而反复切换。本机中控默认使用固定端口16360，被占用时依次尝试后续端口，无需每次随机寻找网页地址。

| 安装包/模块 | 版本 | 升级要求 |
| --- | --- | --- |
| Fabric客户端 | 0.1.9 | 退出客户端后替换旧Mod JAR，保留配置 |
| Paper服务端 | 0.1.3 | 本次未修改，已安装此版无需替换 |
| 内嵌Java协议模块 | 0.1.3 | 已包含在安装包中，不单独安装 |
| 通信协议 | v7 | 客户端0.1.7～0.1.9兼容服务端0.1.3；与旧v6不兼容 |

Minecraft 1.21.11、Java 21；客户端使用Fabric，服务端使用Paper。0.1.8为本地开发构建，未单独发布，本次一并交付其近景视线改动。

## 近景遮挡

- 以眼睛到目标方向的三维距离为准，仅检查前8格，目标更近时止于目标；取消旧的目标末端4格豁免。
- 远端锚点或远端区块不再决定近景视线是否安全。镜头自身占用、完整移动路径、近段未知区块和扫描预算检查仍保留。
- 不改变场景时长、15秒入镜超时、近距飞行/远距传送规则、玩家隐私和服务端巡游资格。复杂地形仍可能等待、跳过或进入地形保护。

## 固定中控端口

- 默认首选 `http://127.0.0.1:16360/`。端口被占用时顺延16361、16362等，最多尝试100个且不超过65535；其他启动错误明确报错。
- **配置 → 本地中控**可查看实际监听地址、起始端口、顺延状态，并保存下次启动使用的首选端口。保存后现有页面保持连接，完整退出并重新启动客户端后生效。
- 游戏内 `/directorweb port`查询，`/directorweb port <1～65535>`保存；也可编辑本机 `config/bilicraft-director-web.properties`。游戏内命令已编译，未单独进行真实输入验证。
- 继续仅监听回环地址，保留Host、Origin及会话令牌验证；每次启动仍生成新的配对令牌，固定端口不固定令牌。

## 验证与附件

- 本地 `build release`通过：客户端249项、协议54项、服务端64项，共367项JUnit测试，失败和错误为0。新增端口占用顺延、重启回到首选端口、旧令牌失效、端口上界和本机配置持久化等检查；JavaScript语法检查通过。
- 实际Fabric 1.21.11开发客户端在隔离Paper世界中，于游戏主线程调用生产地形查询，10组真实方块/加载状态视线查询通过，另核对机位占用与完整路径碰撞仍受检查。此验证属于近景视线开发阶段，未在正式BiliCraft服务器复现原日志的连续切点。
- 实际Fabric开发客户端启动中控并由浏览器点击配置页，验证非法端口拒绝、保存不切断现有监听、配置关闭重开。完整退出并将首选端口及其下一端口占用后，再次启动实际顺延两位，页面显示正确；验证后首选端口恢复16360。
- 本次未修改服务端及协议代码，沿用0.1.7发布的服务端0.1.3。上述真实开发运行不等于最终云端安装JAR的第二次游戏启动验证，未进行正式服长期直播验证。
- 已按yangyv-coding-check检查本次修改及直接相关逻辑。后续仅在用户明确确认发布时提升版本，开发和测试不提前升版。

发布附件取自本tag提交的GitHub Actions成功构建，包含 `bilicraft-director-client-0.1.9.jar`、`bilicraft-director-server-0.1.3.jar`和 `SHA256SUMS.txt`；具体构建链接与SHA-256随GitHub Release登记。
