# BiliCraft 导播：已确认的设计

更新时间：2026-10-16。客户端对外名称为 **BiliCraft 导播**，配套插件为 **BiliCraft 导播服务**。本文区分已实现能力和后续目标；具体实测范围见验证记录，不以设计说明代替验证。

## 当前展示与操作

客户端以观察者自由摄影机展示游戏场景，不录像、不上传截图、不做语音、字幕或自动开播。玩家名字保留，光照、天气和时间保持原样，由用户配置光影。摄影机持续隐藏聊天消息，包括打开命令输入界面时的历史；后台消息接收和玩家的拒绝指令继续工作，其他玩家的正常聊天与私密按钮不受影响。

已实现手动 F8 启停、F9 菜单和客户端本机 WebUI。配置包含八种运镜模式、半径、速度、高度偏移、运动幅度、转向速度上限，以及自动补足、待播数量、场景默认时长和 AI 本机配置。配置项范围见 [控制架构](control-architecture.md)。运行期间普通移动和鼠标转向不能抢走控制；打开菜单或命令输入时暂缓运镜，停止后恢复人工输入。断线重连用于恢复此前手动开启的运行意图，不能覆盖用户主动停止。

玩家、观景点和巡游区域使用统一素材库与播放队列。右方向键跳过当前队列项，左方向键选择上一可用素材插播；切到玩家仍需重新预告。自动模式下，静止目标环绕、移动玩家跟拍、区域采用半径内的平滑八字路线；也可手选跟拍、环绕、推进/拉远、横移、升降、摇镜或静机位。路径只使用已加载附近区块，不因页面选择而自动传送。

本地默认自动补足待播 4 项，可配置 1～12，人工待播最多 64 项。场景/玩家候选并存时按约 80% / 20% 抽选，只向队尾补充，不重排人工项；候选不足时保留已有条目与基础巡游。人工可添加、插入、排序、移除或立即插播，编辑已停止的队列不会自动开播。场景默认 120 秒，范围 30～600 秒，暂停时不计时；当前与下一项卡片支持按条目 ID ±10 秒。

插件缺失、失权或超时后撤销玩家观察并移除队列中的玩家项，Mod 保留本地运行与当前服务器、当前世界的非玩家场景缓存；没有缓存也可使用本地基础环绕。缓存不保存玩家数据，不把旧玩家快照当作实时许可。队列条目保存在内存，切世界时清理；自动补足已实现，建筑自动识别与热力策略尚未接入。

## 世界与权限

已实现 `/director worlds list`、`/director worlds add <实际已加载世界名>`、`/director worlds remove <世界名>`，独立权限为 `bilicraftdirector.worlds.manage`，默认 OP，支持控制台。名称按服务器实际值精确匹配，不猜测下界/末地后缀或地图标识；列表显示实际名称和加载状态。

名单覆盖管理员明确添加的主世界、下界、末地和自定义世界。`worlds.yml` 以真实世界 UUID 持久化，保存最后已知名称和各世界独立的场景、排除区；旧 `world-name` 仅在首次迁移时导入，移除后不会自动加回。不会自动加载世界，也没有跨世界传送。一次快照只提供摄影机当前世界的目标，玩家观察必须同世界。

游戏连接中的世界标识使用运行时 `World#getKey()`，客户端按当前 dimension key 检查授权和场景；可读世界名用于管理，UUID 用于身份持久化，不能互相猜测映射。世界卸载时撤销该世界授权；配置或存储失败时停止全部数据与观察，读取损坏数据不会退回全允许。

摄影机数据权限为 `bilicraftdirector.data.read`，通过真实发送账号的标准 `hasPermission` 校验，支持 LP 组继承；这不是被观察玩家白名单。黑名单管理与世界管理使用各自独立权限，数据访问权不隐含管理权。现有插件只通过已登录游戏连接提供数据，不开放服务器 HTTP 控制接口。

## 玩家观察与退出

观察前服务端向目标本人私密预告 15 秒，未拒绝才允许开始；开始后仍能随时停止。通知含可点击拒绝/停止、长期黑名单入口，按真实操作者与本次随机请求 token 校验，旧按钮不能影响新会话。

玩家可执行 `/director stop` 或 `/tell 摄影机账号 停止跟随`，拒绝后 24 小时内不再选中。`/director blacklist on/off` 控制本人的长期黑名单；管理员可用 `/director blacklist add/remove <玩家名|UUID>` 管理指定身份，需独立的 `bilicraftdirector.blacklist.manage` 权限。黑名单和冷却重启保留，解除黑名单不清除已有冷却。

协议现为 v4，两个安装 JAR 必须同步升级。玩家队列项创建时确定 180～480 秒计划，默认本地随机，可调整下一项 ±10 秒；播出前将计划提交服务端核准，0 仅作为服务端随机选择的源码兼容入口。服务端预告仍保持完整 15 秒，跟随总时长从 FOLLOWING 开始计算。

当前玩家的 ±10 秒必须获得独立服务端回执，不能由客户端单方面延长。服务端只接受真实发送者自有会话、对应目标、180～480 秒范围及严格 ±10 秒差值；预告期调整不重置预告，跟随截止时间固定为最初开始时间加新总时长。非法调整保留有效跟随，合法缩短使截止时间已过时正常结束；延长先持久化覆盖完整时长的冷却预留。具体字段见 [协议说明](../protocol/README.md)。

连续 10 秒无移动、明显转头、挥手或交互则退出；普通结束后冷却 30 分钟。目标拒绝、黑名单、离线、跨世界、远距离传送、进入排除区或隐藏，以及摄影机授权失效时优先结束，不能通过时长调整续接，不追随传送。

黑名单只限制跟随本人，不自动屏蔽附近建筑；建筑隐私通过各世界排除区管理。当前服务端撤销越界数据/观察授权，不代表已经实现完整路径避让。

## 地图与低负载数据来源

当前非玩家目标来自管理员场景、本机 Dynmap 标记/区域导入及非玩家缓存；热力分析尚未实现。已核实的站点入口和数据量见 [Dynmap 核对记录](dynmap-data-findings.md)。Dynmap 世界标识由管理员与实际服务端世界 UUID 显式对应。

按用户最新要求，服务端只提供外链与世界映射等小型元数据，原始 JSON 和瓦片不通过游戏服务器下发。Mod 手动直连外链，异步解析 markers/areas，按 5 分钟缓存/ETag/同源在途任务复用。点击不触发世界扫描或 Dynmap 重渲染。持续热力仍未实现，预算仅为可选方案，见 [服务端负载设计](server-load-design.md)。地标和领地边界不能直接证明建筑密集或机位可通行。

## 客户端本地中控与 AI

AI 二级菜单和 WebUI 支持 DeepSeek 与 OpenAI GPT 的地址、模型、遮挡密钥及策略开关本机保存。策略默认关闭，显式启用后才参与运行中的自动补足；保存配置不会启动导播。密钥须为不含空白的 ASCII 字符串。WebUI 可测试已保存提供方的 `GET /models` 并选择模型，不发聊天请求，也不自动启用策略；测试成功不代表所选模型的 Chat 能力已验证。

WebUI 是 Mod 提供的客户端本机中控：左侧播放队列、中央位置示意图、右侧可搜索素材库，底部操作记录，顶部固定启停与跳过；工作台可实时切换运镜和调整五项参数，完整镜头、队列和 AI 配置也集中在独立配置页。实时参数先应用，点击保存才写盘；所有模式沿现有速度与转向限制平滑过渡。当前与下一项可见计划及剩余时长、±10 秒入口；玩家当前时长显示等待服务端核准。页面展示实际客户端账户与可取得的头像，读取失败有文字占位。它复用游戏内操作与主线程状态，服务端不托管页面。本机接口按需启动，仅绑定回环地址和随机端口，不向公网或局域网开放。

固定 `StrategyPrompt` 与严格选择解析器用于实际文本请求，只读预览包含版本、固定规则及最多 12 个短 ID 候选。AI 只补待播缺口，返回 `{"picks":["c1"]}`，不重排人工队列、不输出低层动作或思维链；请求至少间隔 60 秒，失败同样计入间隔并回到本地补足。DeepSeek 显式关闭思考，输出上限 256 token；OpenAI 对不支持非思考请求的模型拒绝继续执行建议。WebUI 展示客户端会话请求数、已返回 token 用量和用量未返回的请求，后者不视为零成本。移动、运镜和游戏状态始终由 Mod 执行，详见 [AI 决策契约](ai-decision-contract.md)。

Mod 保留独立执行与本地默认能力，本机 WebUI 与 AI 共用 Mod 操作入口，不各自维护执行器。手动停止/暂停优先，服务端玩家隐私和世界约束始终生效；网页不能绕过预告、拒绝或跨世界限制。响应按运行代次、配置版本、世界与最新候选重新核对，失效回包不能撤销手动停止。远程中控和完整策略编辑尚未实现，职责边界见 [控制架构](control-architecture.md)；实际付费 API 是否可用应按独立验证记录判断。

## 保留的后续展示目标

后续仍以建筑密集、较少访问的区域为主。本地已有 80% 场景 / 20% 玩家候选抽选与队列播放，但建筑自动发现、热点权重、区域间有限传送、室内路线规划及完整淡出淡入过渡尚未实现，不能把当前手工场景与基础运镜视为这些功能已经完成。

开发基线保持一个仓库、三个模块、两个安装 JAR：Minecraft 1.21.11 / Fabric Loader 0.18.4 / Fabric API 0.141.3+1.21.11、Paper 1.21.11 API、Java 21。
