# 普通镜头的本地地形避障

普通镜头的本地地形检查自客户端0.1.6开发版加入，首次随v0.1.7发布，减少极高山脉使相机进入山体的问题。v0.1.7的客户端0.1.7、服务端0.1.3、内嵌协议模块0.1.3使用wire v7，从v6升级时因全服名单与授权接近流程需同时更新双端；此要求不来自避障本身。本文保留0.1.6历史实测，不能将旧产物的实测自动算作0.1.7验证，详见[发布说明](releases/v0.1.7.md)。

客户端0.1.8将视线遮挡限定为眼睛前方8格，机位占用和实际移动路径仍做完整安全检查；兼容服务端0.1.3/协议v7，服务端与协议模块版本无需变更。

## 高度与机位

`CameraMotion`仍负责原有构图：场景和本地巡游以用户保存的绝对Y为基准，玩家跟随以玩家中心加独立跟拍偏移为基准。`CameraTerrainAvoidance`只调整当前执行目标，不改写已保存的高度、距离、模式或玩家偏移。

优先在基准高度尝试原方位及多个水平角度，保留目标周围的镜头距离；机位安全但直达路径被挡时，尝试局部水平绕行，并保留已选绕行侧以减少左右反复切换。只有基准高度的构图或局部通路不可用时才尝试临时抬升，搜索受当前世界顶部限制，并细化已找到的最低安全高度区间至0.5格以内。它是有限候选搜索，不能证明找到了所有可能路径中的最低高度。

临时抬升后，基础高度机位及局部路线连续安全2秒才开始回落，每秒最多减小0.5格临时抬升；持续障碍会重新等待。水平角度也等待原方位持续安全后再恢复。执行继续使用既有速度平滑和转向限制，不直接跳变到规划点。改参数、换目标、停止及切世界会清理相应规划状态；原有手动停止、玩家预告授权与隐私检查继续生效。

服务器挂机点是例外：`IdlePoint`仍精确锁定服务端保存的位置和yaw/pitch，完全跳过运镜与避障偏移。避障不擅自修正管理员保存的挂机点，也不改变未运行导播时的原生观察者或人工操作。

## 安全检查与负载

`CameraTerrainWorld`仅在Minecraft客户端主线程读取已加载世界，检查以下条件：

- 摄影机实体占用体积向外扩0.1格后的碰撞盒，使用与观察者noClip独立的方块碰撞查询。
- 从当前位置到候选短路径的扫掠体积，及平滑惯性计算出的实际下一步；下一步独立校验，不能沿旧惯性穿入山体。
- 从摄影机眼睛向目标方向，仅检查三维距离不超过8格的近景视线；目标更近时止于目标。扫描预算、区块加载和射线均使用同一近段，远处墙体、山体、建筑内部锚点和远端未加载区块不参与遮挡判定。旧版末端4格豁免已移除，近处目标前的墙仍须检查。它不保证远处目标无遮挡。
- 当前世界高度、世界边界及已知排除区，空间和路径均受这些限制。

规划每250毫秒执行一次，每个地形查询实例最多使用8192次估算方块扫描；体积与视线查询消耗同一实例预算，实际下一步硬校验另用独立实例。该数字是有界查询预算，不是实测CPU耗时或服务器负载。未加载区块、超出扫描预算的机位、路线或视线返回UNKNOWN，不能当作已确认安全；不主动请求整张地图区块，不增加服务端热力采集。

## 近距飞行与远距传送

既有128格近距FLY与远距TP选择保持不变，不因为障碍或未知区块将FLY升级成TP。

FLY只沿已经确认安全、至多4格的局部路径段前进。远端机位未知时，可以在已确认空闲的局部空间内逐步靠近，以等待沿途加载；局部空间也未知或无通路时停止移动。原有入镜超时与队列跳过机制继续生效，不穿山去“验证”远处机位。实时调参仍重规划FLY，起镜朝向在短暂遮罩内校准，正常飞行过程不全程黑屏。

TP先按原流程在起镜遮罩下到达并等待加载，然后验证实际机位占用和近景视线。客户端0.1.10起，普通场景落点受阻时由`CameraLandingSearch`跨tick保存搜索游标，每250毫秒至多检查16个候选（含高度细化及跨tick安全点复核）；每次使用新的8192扫描预算。先尝试原高度的12个角度，再逐层抬升并搜索各角，最后包含当前世界最高合法机位。空间和近段视线都CLEAR才可修正传送，UNKNOWN只等待后续加载，不能当安全。Dynmap标点Y可能固定，不作为地面或山顶高度依据。

为尽快恢复直播，同高候选之后优先读取落点已加载区块现有的`WORLD_SURFACE`高度图，直接验证最高非空气方块上方至少10格、且满足最低离地设置的机位（默认16格），保留用户基准下限并限制世界顶限；安全即修正，不等待逐层搜索或高度细化。查询前检查区块已加载且已有高度图，不触发区块加载或缺失高度图的整列重建。首次相邻区块未齐时，后续每250毫秒优先重试快路径，不因一次UNKNOWN永久放弃；本轮已经交付的同一表面机位不反复发送。快路径不安全或不可用时才继续增量搜索，真实空间和近段视线验证继续有效。

实际受阻后给予5秒搜索窗口，最多执行6次已确认候选的本人原生TP；已经找到并发出的修正TP仍等待其到达/加载确认，不被搜索截止时间立即撤销。搜索及入镜期间不扣场景时长。成功后以实际机位和最新保存高度重建临时抬升，再由正常运镜继续，不写回配置。每次修正都相对原入镜构图搜索，不累计叠高；若候选到达时被新的方块占据，继续尝试后续候选。初始TP未到达或未加载仍按原15秒等待，近距FLY不升级TP，服务器挂机点仍精确锁定，玩家接近继续服从服务端15秒期限与96格检查。

场景及本地巡游的机位目标还检查真实地表上方的最低离地高度，默认16格，允许0～128格，0关闭；原绝对Y作为基准保留，抬升只在执行期生效。物理路径不因此被禁止，允许相机从偏低但空闲的位置平滑爬升。玩家跟拍不套用此离地设置。普通镜头最大俯仰默认45°、范围5～80°；可开启陡角自动拉远，在距角度上限5°时提前扩大局部构图距离，场景不超过256格、玩家不超过24格。实际移动仍受原速度、转向和碰撞约束，配置中的距离不被改写，固定服务器挂机点保持原位姿。

客户端0.1.11起，`CameraGroundClearance`在速度限幅与惯性平滑之后额外约束实际下一步。它读取当前、预测落点及两个交叉XZ位置的地表，取最高地表加最低离地设置；交叉位置覆盖原版单轴微速度清零和斜跨地表拐角的情况。每步最多4次现有高度图读取，不扫描整列方块。任一地表未知则清零速度等待。尚未达到前方最低高度时先原地平滑抬升，仍位于较高地表上方时不提前下降；最终步骤继续经过物理路径、速度、世界边界、高度和排除区检查。

原版会清零小于0.003格的单轴速度；向上收尾保留至少0.004格、且不超过配置速度的正步长，避免停在高度目标下方。实际步骤约束不改写绝对Y或规划器的临时抬升，不将接近未知地形升级为TP。已经低于新离地设置的空闲机位仍平滑爬升，不瞬移至高度目标。

客户端0.1.12在避障选角之前加入高度前瞻：先读取原候选机位的已加载地表，再沿原路线与已有惯性方向每0.5格读取已加载高度图；局部前瞻最多16格，范围随速度调整。连续ORBIT/AUTO会沿运动方向外推，不将不断移动的瞬时构图点当作路线终点；前往场景和其他固定机位不外推过终点。每tick最多66次额外高度图读取，不扫描方块、不加载区块。最高已知地表加最低离地设置并保留1格余量，形成临时高度下限，统一参与候选空间/近段视线校验、局部路线与速度平滑，避免先为了维持低Y选择另一侧屋顶、之后才发现原路线需要抬升。遇到较低地表时连续稳定两秒后，每秒最多回落0.5格，候选或前方未知时不据此回落。保留高度也用于自动拉远，避免实际高空机位仍朝低Y计算而压缩水平速度。必要的原地爬升和地形等待会暂停运镜相位，恢复后不追赶等待期间积累的构图。

前瞻只用于提前规划，不能证明后续路线安全；末端四列地表、实际扫掠路径及世界限制仍独立检查。突变太高、方块动态变化或区块未就绪时，仍可能先原地抬升或停止等待。玩家跟拍最低离地关闭时不应用这层前瞻，服务端挂机点完全跳过；保存参数不变。

搜索失败或超时后才优先尝试返回最近已确认安全机位；回退也失败、当前机位仍未确认安全时，继续遮挡并暂停排播。客户端0.1.7起使用CameraTerrainRecovery，在真实连接和世界就绪后每250毫秒复查当前占用，仅CLEAR自动解锁并继续补队；BLOCKED或UNKNOWN仍保持等待。解锁不直接清除遮罩，仍经revealShot校准构图后淡入。手动Stop、跳过、换目标或连接/世界变化会清除搜索，迟到检查不能自动启动。没有旧安全机位时也不会凭空生成保证安全的回退位置。

## 实现边界

这是本地有界避障，不是全局寻路，不保证封闭山体、洞穴、狭窄室内、长距离连续障碍或任意地图锚点都存在可达且可见的构图。复杂地形、近段视线跨越未加载区块或预算用尽时，可能等待、跳过或保持遮罩；不能把这些状态称为找到安全路径。山体检查只改善普通镜头执行，不改变场景/玩家比例、轮内去重、玩家拒绝黑名单、服务器巡游名单或排除区语义。
