# 普通镜头的本地地形避障

当前源码客户端0.1.6在既有运镜与平滑执行之间增加本地地形检查，解决极高山脉使相机进入山体的问题。服务端与内嵌协议模块仍为0.1.2、通信协议v6，本次不要求替换服务端；发布标签仍保留v0.1.5，本文不是新标签的发布公告。

## 高度与机位

`CameraMotion`仍负责原有构图：场景和本地巡游以用户保存的绝对Y为基准，玩家跟随以玩家中心加独立跟拍偏移为基准。`CameraTerrainAvoidance`只调整当前执行目标，不改写已保存的高度、距离、模式或玩家偏移。

优先在基准高度尝试原方位及多个水平角度，保留目标周围的镜头距离；机位安全但直达路径被挡时，尝试局部水平绕行，并保留已选绕行侧以减少左右反复切换。只有基准高度的构图或局部通路不可用时才尝试临时抬升，搜索受当前世界顶部限制，并细化已找到的最低安全高度区间至0.5格以内。它是有限候选搜索，不能证明找到了所有可能路径中的最低高度。

临时抬升后，基础高度机位及局部路线连续安全2秒才开始回落，每秒最多减小0.5格临时抬升；持续障碍会重新等待。水平角度也等待原方位持续安全后再恢复。执行继续使用既有速度平滑和转向限制，不直接跳变到规划点。改参数、换目标、停止及切世界会清理相应规划状态；原有手动停止、玩家预告授权与隐私检查继续生效。

服务器挂机点是例外：`IdlePoint`仍精确锁定服务端保存的位置和yaw/pitch，完全跳过运镜与避障偏移。避障不擅自修正管理员保存的挂机点，也不改变未运行导播时的原生观察者或人工操作。

## 安全检查与负载

`CameraTerrainWorld`仅在Minecraft客户端主线程读取已加载世界，检查以下条件：

- 摄影机实体占用体积向外扩0.1格后的碰撞盒，使用与观察者noClip独立的方块碰撞查询。
- 从当前位置到候选短路径的扫掠体积，及平滑惯性计算出的实际下一步；下一步独立校验，不能沿旧惯性穿入山体。
- 从摄影机眼睛到目标的视线；允许最后4格被目标建筑或地形占据，以兼容建筑内部的地图锚点。它不能保证目标整体无遮挡。
- 当前世界高度、世界边界及已知排除区，空间和路径均受这些限制。

规划每250毫秒执行一次，每个地形查询实例最多使用8192次估算方块扫描；体积与视线查询消耗同一实例预算，实际下一步硬校验另用独立实例。该数字是有界查询预算，不是实测CPU耗时或服务器负载。未加载区块、超出扫描预算的机位、路线或视线返回UNKNOWN，不能当作已确认安全；不主动请求整张地图区块，不增加服务端热力采集。

## 近距飞行与远距传送

既有128格近距FLY与远距TP选择保持不变，不因为障碍或未知区块将FLY升级成TP。

FLY只沿已经确认安全、至多4格的局部路径段前进。远端机位未知时，可以在已确认空闲的局部空间内逐步靠近，以等待沿途加载；局部空间也未知或无通路时停止移动。原有入镜超时与队列跳过机制继续生效，不穿山去“验证”远处机位。实时调参仍重规划FLY，起镜朝向在短暂遮罩内校准，正常飞行过程不全程黑屏。

TP先按原流程在起镜遮罩下到达并等待加载，然后验证实际机位占用和目标视线。若不安全，在遮罩内最多两次改为已确认的同高或临时抬升机位，仍由本人原生传送命令执行，权限检查不变。失败或超时后优先尝试返回最近已确认安全机位；回退也失败、当前机位仍未确认安全时，继续遮挡并暂停排播，等待手动停止或选择远处场景。没有旧安全机位时也不会凭空生成保证安全的回退位置。

## 实现边界

这是本地有界避障，不是全局寻路，不保证封闭山体、洞穴、狭窄室内、长距离连续障碍或任意地图锚点都存在可达且可见的构图。复杂地形、视线跨越未加载区块或预算用尽时，可能等待、跳过或保持遮罩；不能把这些状态称为找到安全路径。山体检查只改善普通镜头执行，不改变场景/玩家比例、轮内去重、玩家拒绝黑名单、服务器巡游名单或排除区语义。
