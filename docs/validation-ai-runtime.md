## DeepSeek 真实请求

使用本机已保存的 `deepseek-flash` 配置，通过正式 `AiHttpClient` 发起一次非思考短决策。
输入为公开 Dynmap 景点名称、类型和本地评分，不包含玩家信息、坐标或凭据。

- 实际耗时 466 ms；提供方报告输入 394、输出 15，合计 409 Token。
- 三个短 ID 通过正式 `StrategyPrompt` 解析；正式队列追加三项，保留原人工首项并去重。
- 此项使用真实 API 与正式 Java 类，不等同于 Minecraft 进程内验证。

原始脱敏摘要：忽略目录 `.test/real-deepseek-strategy-smoke.json`。

## 真实 Fabric 客户端与隔离 Paper

使用真实 Minecraft 1.21.11 / Fabric 客户端连接本机 `127.0.0.1:25590` 的
Paper 1.21.11-132 与导播服务协议 v4。离线测试账号为 `AiRuntimeCam`，处于观察者模式，
服务端通过 LuckPerms 授权并提供六个附近测试景点。本轮没有连接正式 BiliCraft 服务器。

临时测试 Mod 在原生窗口创建前隐藏窗口，并在真实客户端主线程调用正式导播控制方法，
使用正式 `LocalControlServer` 鉴权边界。它不生成模拟状态或替代模型响应，未放入发布 JAR。
网络请求、目标合法性检查、队列、计时、运镜及客户端移动包均由正式 Mod 执行。

两次真实策略请求共输入 743、输出 27，合计 770 Token；未返回用量的请求数为零。
观察到的两次请求起始间隔为 61,021 ms（每 500 ms 采样）。

通过的检查：

1. 第一轮 AI 实际向队尾补充四项，并开始播放第一项。
2. 摄影机位置持续改变；隔离服实体数据也确认收到摄影机移动。
3. 30 秒场景播放结束后自然切换下一项，没有通过跳过命令代替计时。
4. 60 秒调用间隔后，第二轮 AI 向队尾补充一项。
5. 手动停止后继续观察三秒，没有再发策略请求，摄影机位移为零。
6. 结束后恢复原 AI 开关与队列配置，导播保持停止。

详细脱敏轨迹：忽略目录 `.test/real-client-ai-runtime-smoke.json`，共 134 个状态样本。
本轮合计三次真实 Chat 请求，共 1,179 Token；这是提供方响应中的用量，不是人民币账单。

本轮证明后台选点、队尾补充、自动切项与停止行为，不包含对最终光影画面及运镜主观平滑度的目视评估。
正式服务器验证单独记录，不能由这次隔离服结果推定。
