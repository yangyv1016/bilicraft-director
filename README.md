# BiliCraft 导播

面向 BiliCraft 纯画面直播展示的双端项目，英文项目名为 `bilicraft-director`。

当前发布 **v0.1.5**：客户端 **BiliCraft 导播 0.1.5**，配套插件 **BiliCraft 导播服务 0.1.2**，内嵌协议模块 **0.1.2**，通信协议 **v6**。本次修复断线清理可能丢失自动重连通知，以及重连加载期间再次断线的重试间隔；服务端未改，已安装0.1.2无需替换。支持客户端本地 WebUI 中控、自动续排与人工插队、实时多种运镜、同世界 OP 场景传送、服务器共享挂机点、区域巡游和附近玩家授权观察；建筑自动发现和跨世界巡游尚未实现。详见[发布说明](docs/releases/v0.1.5.md)。

当前源码客户端为 **0.1.6**，增加普通镜头的本地地形避障：优先保持已保存高度调整水平机位和绕行角度，必要时临时抬升，基础路线持续安全后缓慢回落，不改写配置。服务器挂机点仍严格锁定位姿，不应用避障偏移。服务端与内嵌协议模块保持 **0.1.2**，通信仍为 **v6**，已装服务端无需更换；现有发布标签仍为v0.1.5，未创建新的发布标签。实现边界与本轮验证状态见[地形避障说明](docs/terrain-avoidance.md)。

## 模块与版本

| 模块 | 环境 | 责任 |
|---|---|---|
| `client-mod` | Minecraft 1.21.11，Fabric Loader 0.18.4，Fabric API 0.141.3+1.21.11 | 快捷键、菜单、基础运镜和服务器授权的附近玩家跟随 |
| `server-plugin` | Paper 1.21.11，Java 21 | 数据权限、私密预告、拒绝、黑名单、冷却及状态撤销 |
| `protocol` | 纯 Java 21 | 有界二进制消息、握手与两端共享的数据类型 |

开发工具：Java 21、Gradle Wrapper 9.2.1、Fabric Loom 1.14.10、Yarn 1.21.11+build.4。Mod Menu 17.0.1 为可选入口，F9 菜单不依赖安装 Mod Menu。

发布标签与两端版本独立管理，权威配置为 `gradle.properties` 中的 `release_version`、`client_version`、`server_version` 和 `protocol_version`；只有发生变更的模块升级版本。`protocol_version` 是内嵌Java模块版本，通信兼容性由 `Protocol.VERSION` 独立控制。客户端0.1.3～0.1.6与服务端0.1.2使用v6兼容；不能与v0.1.2及更早发布的v5端混用。每次发布说明列出兼容的客户端/服务端组合。

## 构建

配置 `JAVA_HOME` 指向 JDK 21 后运行：

```powershell
.\gradlew.bat build release
```

输出：

```text
build/release/bilicraft-director-client-0.1.6.jar
build/release/bilicraft-director-server-0.1.2.jar
```

客户端 JAR 已包含协议模块，服务端 JAR 同样已包含协议代码。不要把 `protocol` 单独安装为插件。

依赖首次构建需要联网；如本机 Java 需要代理，在本机 Gradle 用户配置中设置，不将代理凭据或机器绝对路径写入工程。Wrapper 校验官方 Gradle 分发包 SHA-256。

## 云端构建

GitHub Actions 的 [Build and test](https://github.com/yangyv1016/bilicraft-director/actions/workflows/build.yml) 工作流在推送 `main`、向 `main` 提交 PR、推送 `v*` 标签时自动运行，也可在 Actions 页面点击 **Run workflow** 手动触发。

工作流使用 Ubuntu 和 Temurin Java 21，校验 Gradle Wrapper、缓存 Gradle 依赖，并执行 `build release`，包含三个模块的单元测试。成功后可在运行详情的 **Artifacts** 下载 `bilicraft-director-运行编号-尝试次数`，内含双端安装 JAR 和 `SHA256SUMS.txt`，保留 30 天。测试报告独立保留 14 天，构建失败时也会上传已生成的报告。版本标签只触发构建，不自动发布 GitHub Release。

云端构建不启动真实 Minecraft 客户端或 Paper 服务端，也不访问真实 AI 提供方；这些运行验证仍需单独执行。

## 安装与试用

1. 将 server JAR 放入 Paper 的 `plugins/`，移除旧版导播 JAR。内部插件名为 `BiliCraftDirector`，旧版数据目录会自动迁移，详见下方升级说明。首次启动会从旧 `config.yml` 导入默认世界；之后世界名单以 `plugins/BiliCraftDirector/worlds.yml` 为准。
2. 将 client JAR 放入摄影机客户端的 `mods/`，安装上述 Fabric API。普通被观察玩家无需安装 Mod。
3. 给摄影机账号授予 `bilicraftdirector.data.read`。例如通过 LuckPerms：

   ```text
   /lp group 摄影机权限组 permission set bilicraftdirector.data.read true
   /lp user 摄影机账号 parent add 摄影机权限组
   ```

   权限通过 Paper 标准 `hasPermission` 校验，支持 LP 的组继承；这不是被观察玩家白名单，不授予 OP 或通用传送权限。
4. 导播账号进入观察者模式，按 **F8** 手动启停，按 **F9** 打开菜单；也可从 Mod Menu 进入。本地巡游、地图导入、AI选点、队列和运镜默认可用。Mod初始化即在后台异步预取默认Hyperion/Paralon地图，不阻塞客户端或资源包；进入匹配的BiliCraft主世界且没有本机地图覆盖后，等待原版资源包下载/重载完成、世界画面连续稳定2秒，再安全应用预取结果，复用有效缓存或同源在途请求，不定时轮询。其他服务器或世界可在本机 WebUI 配置外链并手动导入，均无需配套插件。玩家观察必须获得实时服务端许可。
5. 菜单可调整半径与速度、手动拉取展示目标，并选择玩家、观景点或巡游区域。同世界合法场景可直接选择，无需事先加载区块。入镜机位按当前摄影机相对目标的 XZ 方位确定；摄影机距该机位的实际三维距离不超过 128 格时平滑飞行，超过时由本人发送 `minecraft:tp @s x y z`，需要服务器授予对应命令权限。未加载区块不会将近距飞行升级为传送；入镜期间暂停场景倒计时，到位且目标区块加载后开始，超时跳过，不自动跨世界传送。玩家观察仍受附近范围与预告授权约束。
6. 在 F9 菜单点击 **本地中控台**，由 Mod 启动本机网页并打开浏览器。WebUI 由客户端托管，服务端无需网页程序或额外端口。

打开菜单或命令输入界面时会暂缓运镜，返回游戏继续。巡游期间普通移动、鼠标转向和世界点击不能抢走摄影机控制；停止后恢复人工输入。仅导播运行时隐藏聊天消息及输入界面内的历史消息；未启动或停止后恢复正常绘制，不清除聊天历史、不修改用户原设置。保留玩家名字、真实光照和底层控制消息。对被观察玩家的正常聊天界面没有影响。

导播运行且没有打开菜单/聊天输入时，**→** 跳过当前队列项，**←** 从素材库选择上一可用素材并立即插播；后一操作不是历史回退。两者都包含场景和玩家，切到玩家仍重新走 15 秒预告。方向键可在游戏按键设置中修改，菜单与输入界面保留原用途。

自动模式下，观景点缓慢环绕，区域使用平滑八字路线，移动玩家采用后侧跟拍。也可实时选择环绕、跟拍、推进/拉远、横移、升降、摇镜和固定机位。运镜在目标区块加载后执行，加载情况不限制场景选点。授权下拉的非玩家场景按服务器地址独立保存在客户端 `config/bilicraft-director-scenes/`；插件缺失、失权或响应超时后撤销玩家观察，保留本地巡游与场景能力。场景缓存不保存玩家数据，巡游资格与排除区另存于本机世界规则缓存；更换世界后重新同步。

普通镜头主动避开山体和有碰撞体积的方块，不依靠观察者穿墙实现绕行。保存的场景绝对Y、玩家独立跟拍偏移仍是基准；先尝试同高构图与短距离绕行，无法获得安全机位时才临时抬升。基础路线连续安全2秒后，以每秒0.5格缓慢恢复临时高度；所有移动继续经过原有速度与转向平滑。未加载或扫描预算不足的空间不视为安全，必要时等待或跳过，而不是穿过未知山体。远处传送在起镜遮罩下验证落点，最多修正两次，失败优先返回先前已确认机位；无法恢复时保持遮罩，等待手动停止或选择远处场景。此功能是有界本地避障，不保证为所有地形找到可达路线，详见[地形避障说明](docs/terrain-avoidance.md)。

导播运行时，游戏画面左上角显示当前排播目标名称，包含观景点、巡游区域和玩家，随目标切换更新；不按摄影机或玩家所在坐标推断地区，没有当前目标或停止导播时隐藏。Dynmap 名称去除 HTML、`§` 和 `&1` 等 Minecraft 颜色/样式码，以统一白字显示。

Dynmap 拉取后自动筛除重复候选：同类型、清理后同名且水平距离不超过128格的标点保留一个原始代表点，保留其ID与坐标；远处同名地点分别保留，原始区域多边形不删除。拉取结果会显示合并数量。

名称先提取地图上的可见标题，不导入 `.toptip{…}`、`.main{…}` 等CSS及创建时间、创建者等隐藏提示。过滤 `newhoroburgh.market_g7` 这类纯ASCII、点分层级的内部标识，以及明确的铁路里程标、道岔、信号机、线路控制节点和系统世界边界候选；保留车站建筑、星门、正常公会地区和正常英文名称（如 `Noah`、`Elysian_Realm`）。旧地图缓存中的内部标识和可识别的CSS残片也不进入候选。状态显示屏蔽数量；筛选不把区域设为禁拍区。

转场采用“先遮挡、直接对准、再淡入”：在黑屏下直接设置新构图的yaw/pitch，并同步上一帧角度，预调整不使用平滑旋转，避免淡入后露出掉头。远处传送等待本人到达、区块加载及朝向就绪后才显示画面；近距飞行只在起镜前短暂遮挡调整，之后飞行过程正常可见。玩家预告和授权规则保持不变，起镜准备不消耗场景时长。

网络请求超时或取消时，旧回复只负责结束原请求，不会用于新一次目标切换。本地场景仍可操作；若旧远程请求始终没有回复，界面会提示重连以恢复远程刷新，不会重新使用玩家许可。

## 内部命名与旧版升级

内部统一使用 `dev.bilicraft.director` Java 包、`BiliCraftDirectorClient` 入口、`bilicraftdirector` Mod ID/资源命名空间、`BiliCraftDirector` 插件名、`bilicraftdirector:director` 游戏通道、`bilicraftdirector.*` 权限和 `/director` 命令。AI 功能本身继续使用 `AiSettings` 等职责名称。

从旧内部命名版本升级时，先退出客户端并停服，备份后移除旧版双端 JAR，再一起安装新版。服务端首次启动将 `plugins/BiliCraftAI/` 整体移动至 `plugins/BiliCraftDirector/`，黑名单、冷却、世界名单和地图映射原样保留；旧目录仍存在且新目录非空时停止服务，须停服核对合并并移走旧目录。若仍安装旧 `BiliCraftAI` 插件，新版拒绝启动。

客户端首次加载时将 `config/bilicraft-ai.properties` 移为 `config/bilicraft-director.properties`，将 `config/bilicraft-ai-ai.local.properties` 移为 `config/bilicraft-director-ai.local.properties`。若对应新文件已存在，使用新文件并保留旧文件，不覆盖。队列、地图和场景缓存此前已使用 director 命名，保持原位置；快捷键标识已更名，自定义按键需在游戏设置中重新核对。

旧 `bilicraftai.*` 授权不再生效，管理员须按原账号/组、显式允许或拒绝及上下文条件重新配置新节点。旧客户端与新服务端不共用通道，必须同步升级；旧 `/aiview` 命令不保留别名，改用 `/director`。

## 客户端本地中控台

网页使用浏览器主要空间：左侧播出/待播队列，中央大幅位置示意，右侧素材库；每条素材直接提供队首/队尾按钮，无需先选中。队首是下一项，不打断当前；立即插播是独立操作。待播项可调序、移除，支持指定插入位置和场景时长。

默认自动保持 **4 个待播选点，不包含当前项**。配置页可设置自动补充、1～12 个前向缓冲、默认场景时长 30～600 秒（默认 120 秒）。玩家新增时默认随机计划 180～480 秒，也可单独指定；当前与下一项均提供 ±10 秒，正在观察的玩家由服务器回执核准后生效，总时长始终从本次跟随开始计算，不能无限续期。预告期间调整不会重置 15 秒。自动补点只使用当前合法候选、补到队尾，不改变人工顺序；两类候选都足够时按场景约 80% / 玩家约 20% 的倾向抽取，不能保证每四项恰好是固定比例。候选不足时不强行凑数；巡游名单内空队列继续基础巡游，名单外等待手动选点。

停止会结束当前项并保留待播，不会因为排队而自行启动。切换世界、断线时清除旧队列；失权后只保留场景能力。场景播放时长在游戏菜单/输入暂停时不消耗，玩家仍受服务端实时授权期限限制。队列配置保存到本机，待播项仅保存在当前会话内。

每次登录维护仅内存的当前轮已播名单：场景到达并开始展示、玩家获准且实际入镜后记入；到达失败和被拒绝的预告不计入。本地自动补点和AI补点都排除已播目标，从剩余合法候选随机抽样；AI候选也不再固定取名称排序靠前的12项。停止再启动、切换世界保留名单，断线或重新登录清空，不写磁盘；手动仍可选点重播。开启自动续排时，当前项及待播队列结束、当前世界合法候选全部播完后，自动开始下一轮，重新随机排播；多个合法点时下一轮首项避开上一轮末项，只有一个合法点时按场景时长循环。仅清除本次候选的已播记录，其他世界进度、失败退避、跳过退避及玩家冷却保留；未播目标暂处退避时等待，地图/快照加载、菜单暂停、请求未完成或候选为空时不换轮。换轮先在本地确定首项，旧AI回包失效，AI的60秒请求间隔保持。

### 挂机点

挂机点由服务器保存，每个世界共用一个机位与注视方向。使用服务端指令，要求 `bilicraftdirector.idle.manage` 权限（默认OP）：

```text
/director idle set                    保存当前位置与当前视线
/director idle set <x> <y> <z> <yaw> <pitch>
/director idle info                   查看服务器保存的机位与方向
/director idle clear                  清除当前世界的服务器挂机点
```

坐标为绝对坐标（机位使用玩家位置Y，不额外叠加眼高或场景高度），方向沿用Minecraft的yaw/pitch，pitch范围−90～90。
机位按世界UUID保存在 `plugins/BiliCraftDirector/idle-points.yml`，服务器重启和世界改名后保留；需要配套插件。客户端 `/directoridle set [x y z yaw pitch]`、`info`、`clear` 仍可使用，会通过本人原生命令上传服务端，由服务端校验权限与边界、保存并回传。其他授权导播同步收到同一世界的点位；握手、心跳及切世界重新同步。原本机挂机点文件保留在磁盘但不再读取或自动上传，首次使用请重新执行set。服务失联、断线或切世界后清除客户端的该点；其他本地观景功能不受影响。
设置后，游戏菜单和WebUI素材库会出现“挂机点”，可筛选、手动插播、入队，也参与自动及AI补点；时长沿用场景设置（30～600秒，默认120秒），播完后切到下一项，本轮已播后不再自动补入，下一轮重新参与，仍可手动重播。

切入时用本人账号的 `minecraft:tp` 命令直接到保存位置及方向，需要本人tp权限；到达并加载后锁定机位和yaw/pitch，完全不运镜，不受全局环绕、距离、高度等参数影响。入镜等待不消耗播出时长；中控台禁用该镜头的实时运镜控件，原有参数留给其他目标。挂机点继续遵守巡游资格、世界边界、世界高度及已知排除区，不自动跨世界。修改或清除正在播出的挂机点会停止导播，之后需手动重新启动。

工作台提供实时运镜区，选择模式或拖动距离/速度/场景 Y/跟拍高度/幅度/转向滑杆立即应用，经客户端速度与转向限制平滑前往机位。默认参数为 **ORBIT 环绕、距离 136 格、速度 2.5 格/秒、绝对 Y=122、玩家跟拍高度 4 格、幅度 8 格、转向 30 度/秒**；已有显式保存的设置继续保留。连续拖动合并为最新参数，不逐帧写盘；点击“保存当前运镜”保留设置，手动停止时调整不会自动启动。距离 6～256 格、速度 0.5～5 格/秒、场景绝对 Y 为 −64～256、玩家跟拍高度 1～12 格、幅度 2～24 格、转向 6～80 度/秒。场景与本地巡游使用绝对 Y，不叠加目标海拔；玩家按相对高度随玩家升降，跟拍距离保持在 24 格以内。场景使用配置的镜头距离，不受地图标记半径收紧，仍检查世界边界、高度和已知排除区。固定机位和摇镜会先平滑入镜。近距入镜起镜前先遮挡并直接对齐，飞行过程正常显示，场景倒计时暂停；飞行过程中实时调参会重规划飞行路线，不升级为传送。

独立完整配置页集中管理所有已实现的本机业务设置：全部镜头参数、队列参数和两家 AI 提供方。未应用草稿不会被轮询或工作台实时操作覆盖。密钥空白表示保留现有值，明确选择清除时才删除；玩家预告、拒绝和世界权限属于服务器规则，只读展示。

顶部显示真实 Minecraft 账户名与头像。头像来自已经加载的皮肤和本机默认资源，保留头饰层，在本机缓存；不访问第三方头像服务、不读取游戏全帧或上传截图。

底部可切换游戏聊天与操作记录，折叠后保留工作台空间。聊天接收缓冲只在客户端内存保留最近 100 条纯文本，断线清空，不写入磁盘，也不解析 HTML、链接或服务器聊天按钮。输入框支持最多 256 字符的单行消息或 `/命令`，由当前本人账号通过 Minecraft 原生聊天/命令入口发送，继续受客户端聊天限制和服务器权限约束。离线禁用发送，失败保留当前页面中的输入草稿，成功后才清空。WebUI 发送不额外加入客户端原生命令历史；Minecraft 自身和服务器原有日志行为不变，不代表服务器不记录消息或命令。

本机接口只绑定 `127.0.0.1` 随机端口，入口携带每次启动生成的会话令牌，游戏退出后一同关闭。网页状态每秒读取 Mod 当前已有数据，不因网页轮询向服务器刷新候选或扫描世界；自动队列候选不足时最多每 60 秒尝试刷新，人工刷新仍受一秒响应间隔与请求串行限制。操作复用游戏内的执行与隐私校验。状态接口不会返回 API Key，网页不记录输入密钥。

中央地图是候选位置示意，包含手工场景与本机导入的 Dynmap 标记，**不是游戏画面或 Dynmap 栅格瓦片底图**。页面提供外链地图入口；热力分析仍未实现。详细职责见 [本机中控架构](docs/control-architecture.md)。

## 世界与地图来源

管理员可以使用 `/director worlds list`、`/director worlds add <实际世界名>`、`/director worlds remove <世界名>` 管理**自动巡游名单**，权限为 `bilicraftdirector.worlds.manage`。名单外停止基础自动巡游、本地自动补点和 AI 补点，允许手动选择、加入队首/队尾和展示；玩家预告、拒绝、黑名单、冷却、排除区和本人命令权限仍然有效。移出名单会移除自动待播项并停止自动当前项，保留手动项和该世界的场景、排除区、地图资料；重新 `add` 可恢复自动巡游。命令输入精确实际世界名，文件按世界 UUID 保存，不会自动加载世界或跨世界传送。

`worlds.yml` 使用 `version: 2`，每个世界增加 `automatic-patrol: true/false`；旧 version 1 条目自动迁移为 `true`。独立世界规则包下发当前世界 UUID、巡游资格和完整排除区，不依赖配置 Dynmap 外链；客户端按服务器与世界缓存，失联后继续遵守已知规则。首次发现配套插件时等待规则同步再自动补点，手动入口保持可用；没有插件且无已知规则时沿用本地巡游。协议升级为 v5，双端 JAR 须同步更新。

Dynmap 世界名与服务器世界名显式对应。管理员用 `/director map set <实际已加载世界名> <Dynmap世界标识> <地图部署基础URL>` 配置，`map status/clear <世界名>` 查看或清除，权限 `bilicraftdirector.map.manage`；不要求该世界加入巡游名单。映射独立存于 `map-sources.yml`，按服务端世界 UUID 关联，不自动加载世界。提供的地图部署基础 URL 为 `https://map.bilicraft.com/s2/hyperion/`；Dynmap 世界标识有 `Paralon` 等，必须映射到实际对应世界，不能照抄猜测。

也可在 WebUI「配置 → 地图数据」为当前服务器与世界填写本机地图基础 URL 和 Dynmap 世界名。两项都填或都清空；本机配置优先，按服务器地址和世界隔离保存。BiliCraft 主世界没有本机覆盖时使用内置 `https://map.bilicraft.com/s2/hyperion/` 与 `Paralon`；Mod初始化即异步预取该默认来源，不依赖进服或打开中控，不阻塞客户端与原版资源包。进入匹配的BiliCraft世界后，等待原版资源包下载/应用和世界画面连续稳定2秒，再将结果应用到当前世界；复用有效缓存或同源在途请求，过期缓存正常刷新，不定时轮询。其他服务器和世界需使用手动配置的本机或服务端映射。保存配置本身不会下载；手动点击“拉取地图”可更新当前来源，无需配套插件。未配置本机映射时，可使用已授权服务端提供的映射。已知服务端排除区继续约束本地执行。

原始 JSON、瓦片和全量景点不通过 Minecraft 服务器下载或转发。客户端异步解析、5 分钟缓存、ETag 条件请求及同源并发合并，2MiB / 20秒限制；失败保留旧缓存，成功空结果清除旧同源景点。地图结果最多 4096 项；当前世界的全部导入场景进入素材库，不按距离、已加载区块或磁盘缓存大小截断，不可执行项显示为不可用。实际执行仍检查边界和排除区，到达后才运镜。仅磁盘非玩家缓存限 64 项 / 30KB；默认来源在Mod初始化时异步预取，进服、重连或切换世界时复用有效缓存或同源在途请求，缓存过期正常刷新，不做定时下载。预取不等待资源包，结果应用仍检查当前世界匹配并等待资源包及世界加载结束，其余来源手动更新。本机来源在服务端失联后仍可手动拉取，当前已导入的全量场景保留，玩家观察停止。已用实际外链导入候选，来源见 [Dynmap 核对](docs/dynmap-data-findings.md)；持续热力仍未实现，详见 [负载方案](docs/server-load-design.md)。

客户端0.1.6已在真实PCL `bc`实例核对初始化预取：日志记录02:37:50启动默认地图HTTP、02:37:54得到623项候选和360个区域、02:37:55才连接BiliCraft，确认下载无需等进服或打开中控。验证未改动启动参数，本机日志为`.test/default-map-startup-runtime.log`。这项证据针对真实初始化下载顺序，不代表其他服务器映射、所有资源包组合或长时间运行均已验证；本轮其他验证状态见[地形避障说明](docs/terrain-avoidance.md#本轮验证状态)。

## AI 本机配置

在 **F9 导播菜单 → AI 配置** 或本机 WebUI 的 **配置 → AI 提供方** 中选择 **DeepSeek（DS）** 或 **OpenAI GPT**，分别填写 API 地址、模型 ID 和 API Key。两家提供方的配置独立保留；切换提供方不会清空另一家的草稿。API Key 需为不含空白的 ASCII 字符串，不要粘贴字段名、引号或说明文字。

点击 **保存到本机** 才会写入配置；**返回** 或 Esc 放弃未保存改动。配置文件位于游戏实例的 `config/bilicraft-director-ai.local.properties`，包含明文密钥，只供本机使用，不要分享或提交；项目已通过 `*.local.properties` 排除该文件及保存用的临时文件。界面始终以星号遮挡密钥，禁止复制/剪切密钥字段，也不会在朗读提示中读出密钥，支持从剪贴板粘贴。配置不会发送给服务器，保存错误也不会记录字段或异常中的密钥内容。

AI 策略接入已实现，**默认关闭，需显式启用并保存**。仅在导播已手动运行、自动补足开启且队尾缺少合法候选时请求模型；保存配置不会启动导播。两次策略请求至少间隔 60 秒，失败也计入间隔，期间继续本地选点。DeepSeek 显式关闭思考，输出上限 256 token；OpenAI 使用同样的输出上限，不支持非思考参数的模型会失败并回退本地。

WebUI 的 **测试已保存的连接** 只请求 `GET /models`，不发聊天请求、不启用策略，也不计入策略 token 统计。可先保存地址和密钥、将模型暂留空，测试后选择模型，再保存并启用。模型列表可读取不代表所选模型的 Chat 能力或非思考模式已验证。页面显示本次客户端会话的策略请求数、输入/输出 token、合计和用量未返回的请求；未返回用量不能视为零消耗。保存成功也不代表地址、密钥或模型已通过付费 API 验证。

固定短决策协议与只读预览由 `StrategyPrompt` 提供：Mod 先过滤/评分，最多给模型 12 个带短 ID 的候选，只允许返回 `{"picks":["c1",...]}` 补到队尾；不发送真实目标 ID、轨迹或玩家姓名，不要求解释和运镜分析。未知、重复或超量选择整批拒绝，回包后还会检查运行状态与候选是否仍可用。协议和实际非思考请求形状见 [AI 决策契约](docs/ai-decision-contract.md)；预览本身不触发模型请求。

默认地址依据 [DeepSeek 官方文档](https://api-docs.deepseek.com/) 与 [OpenAI API 官方文档](https://developers.openai.com/api/reference/overview)；也可填写符合 HTTP(S) 格式的自定义基础地址。

## 玩家隐私闭环

- 服务端先向目标玩家发送只有本人可见的 **15 秒预告**，含可点击的拒绝/停止、长期黑名单按钮。摄影机等待期间不开始跟随。
- 每个按钮绑定该次请求的随机令牌，由服务端验证实际操作者、请求和有效期。其他玩家、过期或重复旧按钮不能取消无关的新会话。
- 玩家点击拒绝，或执行 `/director stop`，或私聊摄影机 `停止跟随`，服务器立即撤销会话并通知对应摄影机，24 小时内不再选中该玩家。
- `/director blacklist on` 持续禁止被跟随；`/director blacklist off` 解除；`/director status` 查看个人状态。黑名单和 epoch 冷却写入服务端 `privacy.properties`，重启保留。
- 管理员可使用 `/director blacklist add <玩家名或UUID>` 和 `/director blacklist remove <玩家名或UUID>`，权限为 `bilicraftdirector.blacklist.manage`，控制台同样可用。名字仅解析在线或本机已缓存身份；未知名字使用 UUID。加入后立即撤销观察，移除不清除已有冷却。
- 未拒绝后，服务端核准 3～8 分钟观察（未指定则随机），允许本次总时长按 ±10 秒调整。目标连续 10 秒无移动、明显转头、挥手或交互表现则结束；普通结束冷却 30 分钟。
- 离线、跨世界、进入排除区、目标远距离传送（首版 32 格阈值）、客户端心跳超时或摄影机失去权限/观察者模式时撤销。
- 偏好读写出错会明确记录并停止全部观察，不能把损坏数据当作空黑名单。

客户端通过游戏连接收取服务端结构化数据，服务端插件不开放 HTTP API。本机 WebUI 仅操作 Mod，不代替服务器签发观察许可。摄影机聊天隐藏不会妨碍玩家拒绝。服务端的隐私状态是权威，客户端不能自行将预告改成许可。

## 阶段范围与限制

已实现第一阶段的双端骨架、协议、权限、私密可点击预告、拒绝与黑名单持久化、本地启停、基础环绕与附近授权跟随。

以下为已确认的后续目标，**当前版本没有实现**：

- 建筑自动发现和跨区域热点选取；当前 Dynmap 标记/区域只是地图候选，不能等同建筑实体识别。
- 服务端活跃/建造热力图与内部热点数据。
- 远程中控与完整策略编辑；当前已有客户端本机 WebUI 和 DeepSeek/OpenAI 纯文本队尾选点，执行与最终检查仍在 Mod，见 [策略控制架构](docs/control-architecture.md)。
- 跨世界传送、完整路线编辑与室内路线。当前已有同世界 OP 场景传送、多种基础运镜与跟随切换淡入淡出，不能当作完整路线和过渡系统。
- 全局寻路与完整区域路线规划：普通镜头已有受世界边界、排除区、加载状态与扫描预算约束的本地地形避障；它不保证绕过封闭山体、洞穴或所有复杂地形，也不替代完整路线规划。

自动重连恢复断线前正在运行的导播：首次等待10秒，连接失败后每30秒重试，无次数上限；重连加载期间再次断线也按30秒重试。断线通知通过独立线程安全队列交给客户端tick，避免被原版断线清理的cancelTasks丢弃；旧玩家/世界对象仍存在时不会误判成功。清理/加载临时界面不取消，返回标题或服务器列表、手动停止会取消。新的进服事件、资源包下载/应用完成且世界画面连续稳定2秒后才恢复，仍要求观察者模式，旧玩家观察必须重新授权。初始导播握手也等待进服就绪，已建立连接的心跳在后续资源重载时保持。这里只观察原版资源包状态消息，不修改下载地址、接受选项、下载/重载流程和回执。断线通知交付修复包含于v0.1.5，真实重连与首进资源包验证范围以验证记录为准。开发电脑本机通过不代表用户的另一台 13600KF / 32GB / RTX 4070 机器或线上资源包/光影已验证。

不包含录像、截图上传、语音、字幕、数字人、弹幕和自动开播。
