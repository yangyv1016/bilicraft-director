# BiliCraft 导播

让观察者账号自动巡游服务器，展示建筑、观景点和获准跟随的玩家。你可以在本机网页安排播放队列、调整镜头，再用自己的直播软件采集游戏画面。

[下载最新版](https://github.com/yangyv1016/bilicraft-director/releases/latest) · [安装与首次使用](#安装与首次使用) · [玩家如何拒绝观察](#玩家如何拒绝观察) · [服主配置](#服主配置) · [开发与技术资料](#开发与技术资料)

**普通玩家不需要安装 Mod。** 收到观察预告后，可以直接点击拒绝按钮，或用[玩家指令](#玩家如何拒绝观察)停止、长期禁止跟随。

## 先看你需要哪一部分

| 你的用途 | 需要准备什么 |
| --- | --- |
| 用自己的账号展示建筑、地图景点 | 安装客户端 Mod，准备观察者账号；远处选点还需要本人传送权限 |
| 让导播跟随服务器玩家 | 服主安装配套插件，并给导播账号授予数据权限；玩家无需安装任何东西 |
| 管理巡游世界、挂机点和玩家黑名单 | 使用配套插件的管理员指令，见[服主配置](#服主配置) |

本地巡游、地图导入、队列和运镜可以独立使用。AI 选点是可选功能，默认关闭；未启用时由本地策略自动排播。

## 安装与首次使用

### 1. 安装客户端

从 [Releases](https://github.com/yangyv1016/bilicraft-director/releases/latest) 下载客户端 JAR，放入**实际启动的游戏实例**的 `mods/` 目录。升级时退出游戏，移走旧版导播 JAR，保留配置。

| 项目 | 要求 |
| --- | --- |
| Minecraft | **1.21.11** |
| Java | **21** |
| Fabric Loader | **0.18.4 或以上** |
| Fabric API | 对应 Minecraft 1.21.11，**0.141.3+1.21.11 或以上** |
| 客户端安装包 | `bilicraft-director-client-0.1.12.jar` |
| 可选菜单入口 | Mod Menu；未安装也能用 F9 |

需要玩家跟随时，再请服主安装 `bilicraft-director-server-0.1.3.jar`，按[服主配置](#服主配置)完成授权。普通观景可以先从客户端开始。

### 2. 进入服务器并准备账号

使用导播账号进入服务器，切换为**观察者模式**，等待资源包和世界加载完成。具有对应权限时，可使用 `/gamemode spectator`。

远处景点会由这个账号执行 `minecraft:tp`，请确认账号有相应命令权限。插件的数据授权不会自动授予传送或切换游戏模式的权限。

### 3. 打开本地中控

客户端启动完成后会自动监听本地中控端口。首次可按 **F9 → 打开本地中控**，或在游戏内输入 `/directorweb`，打开当前实际地址；也可以直接访问默认地址。

默认地址为 `http://127.0.0.1:16360/`，占用时自动顺延，以游戏打开的实际地址为准。保留网页即可在客户端重启后自动重连，无需每次回游戏重新配对；启动和重连中控不会自行开播。

如果实际端口发生变化，需从游戏入口打开新地址；页面只重连当前地址，不扫描其他端口。升级前已经打开的旧页面先刷新一次，以载入新的重连逻辑。

**打开网页后，回到游戏关闭导播菜单或暂停菜单，再切回浏览器操作。** 游戏菜单保持打开时，运镜会暂停。

如果每次切到浏览器，游戏又自动弹出暂停菜单，请在游戏内按 **F3+P**，根据聊天提示确认已关闭“失去焦点时暂停”，再返回浏览器。

### 4. 准备素材并开始

1. 在右侧素材库查看观景点、巡游区域和玩家。
2. BiliCraft 匹配的主世界会自动使用内置地图来源，加载就绪后将景点加入素材库；可以点 **拉取地图** 手动刷新。其他服务器或世界见[地图配置](#地图配置)。
3. 点击素材上的**加入队尾**或**队首**，也可以保留自动补队，让本地策略选择目标。
4. 按 **F8** 或在网页点击启动，开始导播。

默认自动保持 **4 个待播目标**，不包含当前项；普通场景默认展示 **120 秒**，播完自动接续。添加素材、打开网页或保存配置都不会自行启动导播。

### 5. 停止与恢复人工操作

按 **F8** 或在网页点击停止。停止会结束当前项并保留待播队列，恢复正常移动、鼠标转向和聊天显示。关闭浏览器页面不会停止导播。

## 日常怎样操作

### 排队与插播

中控台左侧是播出与待播队列，中央是位置示意，右侧是素材库。

| 操作 | 结果 |
| --- | --- |
| 加入队尾 | 排到现有待播内容后面 |
| 队首／插到下一项 | 成为下一项，当前内容继续播放 |
| 立即插播 | 打断当前项，开始准备所选目标；玩家仍需预告 |
| 调整顺序、移除 | 直接管理待播队列 |
| 当前播出／下一项的 ±10 秒 | 调整展示时长；玩家时长由服务器确认 |
| 配置 → 队列 | 开关自动补队，设置待播数量和默认场景时长 |

待播数量可设为 **1～12**，场景时长 **30～600 秒**。玩家跟随总时长为 **3～8 分钟**，准备入镜不占展示时间。自动选点偏向建筑场景，场景与玩家均充足时约为 **80%／20% 的随机倾向**，不是固定轮次。

自动补充只加到队尾，保留人工顺序。同一轮优先展示未播目标，候选播完后自动进入下一轮；手动仍可重播。断线或切换世界会清除待播队列。

### 调整镜头

工作台的**实时运镜**可以直接切换模式、拖动参数，镜头会经平滑移动衔接。满意后点击 **保存当前运镜**，下次启动继续使用；其余本机设置集中在**配置页**。

可选模式包括自动、环绕、跟拍、推进／拉远、横移、升降、摇镜和固定机位。

| 常用参数 | 怎样理解 |
| --- | --- |
| 距离 | 场景镜头距目标的水平距离，6～256 格，默认136格；玩家跟拍距离最多24格 |
| 场景 Y | 场景镜头的绝对 Y 坐标，默认122，不叠加景点海拔 |
| 场景最低离地 | 镜头至少高于脚下真实地表多少格，默认16；必要时临时抬升，保留保存的场景 Y |
| 跟拍高度 | 随玩家升降的相对高度，默认4格 |
| 最大俯仰角 | 默认45°，避免过陡；开启“陡角自动拉远”后会平滑增加距离改善构图 |

默认还使用速度 **2.5 格/秒**、幅度 **8 格**、转向 **30 度/秒**。已有保存参数继续保留。

近处目标平滑飞行，远处目标传送后淡入；起镜准备期间场景倒计时暂停。普通运镜会尝试避开山体，提前参考附近地表平滑抬升，通过高处后缓慢回落，减少环绕与升高交替停走；复杂地形可能等待或跳过。服务器挂机点保持固定位置和视线，不使用这些运镜参数。

### 快捷键与聊天

| 按键／入口 | 用途 |
| --- | --- |
| **F8** | 启动／停止导播 |
| **F9** | 打开游戏内导播菜单 |
| **→** | 跳过当前队列项 |
| **←** | 选择上一可用素材并立即插播；不是返回上一段录像或回退队列 |
| 网页底部“游戏聊天” | 发普通消息或 `/命令`，也可切换到操作记录 |

在底部打开 **事件与操作 → 玩家观察**，可查看这台摄影机的申请、预告、入镜、开始、结束及跟随时长调整。每条显示客户端记录时间、玩家名、服务端或本地来源和具体原因；玩家拒绝、加入黑名单、无动作结束及授权失败不会再随下一目标覆盖。服务端合并说明的原因会原样显示，不猜测具体是哪一项。

客户端保留最近 **200 条观察事件**，刷新网页或重新连接中控可恢复；**清空显示**只影响当前页面。点击 **导出观察记录**可保存当前客户端内存中的观察事件。退出客户端后，这些网页历史不再回载；需要检查更早记录时，在该游戏实例的 `logs/latest.log` 或归档日志中搜索 **`[ObservationEvent]`**。事件不包含观察授权令牌、聊天原文、坐标或 API Key；没有当前观察会话的全服黑名单变更不会广播到这里。

快捷键可在游戏按键设置的 **BiliCraft 导播**分类修改。方向键只在导播运行且未打开游戏菜单／聊天输入时接管。

运行时会接管普通移动、转向和交互，并隐藏游戏聊天绘制，保留玩家名字；停止后恢复。游戏画面左上角显示当前展示目标名称。打开游戏菜单或输入界面会暂停运镜，已授权的玩家跟随期限仍由服务器实时计时。

中央地图是**素材位置示意**，游戏画面仍需由直播软件采集；网页还提供外链地图入口。

## 地图配置

BiliCraft 匹配的主世界已内置默认地图，通常无需填写地址。Mod 启动时在后台预取，进入匹配世界并完成资源包及世界加载后应用。

其他服务器或世界：

1. 进入要配置的世界，打开 **配置 → 地图数据**。
2. 填写 **Dynmap 地图基础 URL** 和对应的 **Dynmap 世界标识**。两者来自实际地图部署，世界标识不一定等于游戏里的世界名。
3. 保存本机配置，然后点击 **拉取地图**。保存本身不会下载。

本机映射优先于服务端提供的映射，按服务器与世界分别保存。地图由客户端直连外链下载，游戏服务器只提供映射与规则。素材库会导入当前世界的全量有效候选，并合并附近同名重复点。

## AI 选点配置

在 **配置 → AI 提供方**选择 DeepSeek 或 OpenAI，填写 API 地址和 API Key，保存后可用**测试已保存的连接**获取模型列表。选择模型，再保存并显式启用策略。

AI 只接收筛选后的候选文本，决定补到队尾的目标，实际运镜与最终检查由 Mod 执行。策略请求至少间隔60秒，失败时继续本地选点；启用后会产生提供方 API 用量，页面显示本次会话的 token 统计。

连接测试只读取模型列表，不代表该模型的策略请求已经成功。密钥保存在当前游戏实例本机，不要分享包含密钥的配置文件；详细设置见[技术参考](docs/technical-reference.md#ai-本机配置)。

## 玩家如何拒绝观察

**无需安装 Mod，也不需要管理员权限。** 配套插件会在跟随前私密通知你，保留15秒拒绝窗口，消息内有拒绝／停止和长期黑名单按钮。开始跟随后仍可随时拒绝。

| 指令 | 效果 |
| --- | --- |
| `/director stop` | 拒绝或停止别人观察自己，24小时内不再选中自己；没有当前观察时也可提前使用 |
| `/tell <摄影机账号> 停止跟随` | 拒绝这个摄影机当前对自己的观察 |
| `/director blacklist on` | 长期禁止跟随自己，直到主动解除，服务器重启后保留 |
| `/director blacklist off` | 解除长期黑名单，已有冷却仍然有效 |
| `/director status` | 查看自己的黑名单和冷却状态 |

这里的 `/director stop` 是**玩家拒绝被观察**。导播操作者停止整个导播请使用 F8 或网页停止按钮。

连续10秒无移动、明显转头、挥手或交互，或离线、跨世界、远距离传送、进入排除区，都会提前结束观察。当前版本在预告和接近期间也检查10秒无动作；普通结束后冷却30分钟，主动拒绝后冷却24小时。黑名单只限制玩家跟随，不自动排除周边建筑。

## 服主配置

### 安装与授权

将 `bilicraft-director-server-0.1.3.jar` 放入 **Paper 1.21.11 / Java 21** 服务器的 `plugins/`，停服移除旧版导播 JAR后再启动，保留插件数据目录。

通过 LuckPerms 给摄影机账号授权，例如将下面的账号占位符换成实际名字：

```text
/lp user <摄影机账号> permission set bilicraftdirector.data.read true
```

也可把该节点授给已有权限组，由摄影机账号继承。**此数据权限默认关闭，OP 也需要显式授予**；它不是被观察玩家白名单，也不包含传送权限。

### 允许哪些世界自动巡游

先用 `list` 核对实际世界名，再添加已加载世界：

```text
/director worlds list
/director worlds add <实际已加载世界名>
/director worlds remove <世界名>
```

名单控制自动巡游与自动／AI补队。名单外仍可手动选点、入队和展示，界面显示“仅手动”。移除世界会保留地图和场景资料；不会自动加载世界或跨世界传送。

### 地图、挂机点与黑名单

| 要做的事 | 命令 |
| --- | --- |
| 配置世界地图外链 | `/director map set <实际已加载世界名> <Dynmap世界标识> <地图部署基础URL>` |
| 查看／清除地图映射 | `/director map status <世界名>` ／ `/director map clear <世界名>` |
| 保存当前世界的固定机位和视线 | `/director idle set`，在游戏内站到所需机位后执行 |
| 查看／清除固定机位 | `/director idle info` ／ `/director idle clear` |
| 将玩家加入／移出观察黑名单 | `/director blacklist add <玩家名或UUID>` ／ `/director blacklist remove <玩家名或UUID>` |

以上分别需要 `bilicraftdirector.map.manage`、`idle.manage`、`blacklist.manage`，世界名单需要 `worlds.manage`，这些管理权限默认授予OP；实际完整节点均以 `bilicraftdirector.` 开头。

挂机点会进入素材库并参与排播，切入后完全锁定位姿；修改或清除正在播出的挂机点会停止导播。完整坐标用法、配置文件和升级迁移见[服务端手册](server-plugin/README.md)与[技术参考](docs/technical-reference.md)。

## 常见问题

| 现象 | 先检查什么 |
| --- | --- |
| 启动后镜头不动 | 是否为观察者、资源包是否加载完、游戏菜单／聊天输入是否仍打开；查看中控状态和操作记录 |
| 显示“运行中”，却不自动补队 | 查看是否“仅手动”，让管理员核对巡游世界名单；再检查自动补队开关、地图素材和地形保护状态 |
| 看不到玩家，或玩家不可用 | 需要配套插件及摄影机数据授权，点“拉取目标”刷新；其他世界、无动作、隐私设置和冷却都可能使玩家不可观察 |
| 很少选到玩家 | 玩家约20%是随机倾向；已播、已排、冷却或不可观察的玩家不会自动重复加入 |
| 客户端重启时网页离线 | 保留页面等待客户端启动完成后自动重连；升级前旧页面先刷新一次。实际端口变化时，从 F9 菜单或 `/directorweb` 打开新地址 |
| 地图保存后没有素材 | 保存只记录来源，还需点“拉取地图”；核对当前世界与 Dynmap 世界标识是否对应 |
| 远处景点一直无法到达 | 核对本人 `minecraft:tp` 权限；到达还需等待加载，并通过边界、排除区和机位检查 |
| 显示“地形保护” | 当前机位尚未确认安全，保持遮罩并等待恢复，也可手动停止或选择其他安全景点；不会强行穿山 |

玩家名单来自**当前 Paper 后端**的全体可公开其他在线玩家，不按距离或客户端是否已加载筛选；不汇总代理下其他后端。授权后会刷新一次，运行且自动补队开启、未暂停和无业务请求占用时约每60秒更新。完整规则见[玩家名单与授权观察](docs/full-player-roster.md)。

断线前正在运行的导播会尝试重连：首次等待10秒，失败后每30秒重试。返回标题／服务器列表或手动停止会取消；重新入服且加载就绪后才恢复，玩家观察重新预告授权。

## 开发与技术资料

当前发布 **v0.1.12**：客户端 **0.1.12**，服务端 **0.1.3**，内嵌协议模块 **0.1.3**，通信协议 **v7**。服务端已为0.1.3时无需随本次客户端升级更换；0.1.10已撤回，请使用0.1.12。旧v6组合不能与v7混用，详见[发布说明](docs/releases/v0.1.12.md)。

需要自行构建时，在仓库根目录配置 JDK 21 并运行：

```powershell
.\gradlew.bat build release
```

安装包输出到 `build/release/`。普通使用直接下载发布包即可，协议模块已内嵌，无需单独安装。
